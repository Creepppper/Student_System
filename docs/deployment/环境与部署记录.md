## 2. 源码版本与结构

后端使用 RuoYi 3.9.2 的 `springboot3` 分支，Spring Boot 3.5.16，目标 Java 17。聚合模块为 `ruoyi-admin`、`ruoyi-framework`、`ruoyi-system`、`ruoyi-quartz`、`ruoyi-generator` 和 `ruoyi-common`。`ruoyi-admin` 依赖 MySQL Connector/J，具体驱动版本由 Spring Boot BOM 管理。

上游根 POM 固定声明了阿里云 Maven 仓库，但该域名在当前环境无法解析；项目已删除这两个自定义仓库块，改用 Maven 默认 Central。依赖坐标和版本没有变化。当前沙箱仍禁止 Maven/JVM 建立下载连接，因此这一修改尚未完成真实依赖解析验证。

前端使用独立的 RuoYi-Vue3 3.9.2。`package.json` 固定 Vue 3.5.26、Vite 6.4.1、Element Plus 2.13.1 和 Pinia 3.0.4。上游没有锁文件，也没有 `engines` 字段。本项目选择 npm；首次联网安装后应提交 `package-lock.json`，后续统一使用 `npm ci`。

## 4. MariaDB 初始化方案

执行 `database/init_database.sh` 前，应确认本机 MariaDB 正常并同意脚本调用 `sudo mariadb`；该入口使用 Fedora 的 unix_socket 管理员认证，不修改 root 密码或认证方式。新数据库采用 `utf8mb4` 与 `utf8mb4_unicode_ci`，并创建只能从本机连接、仅有该库 `SELECT`、`INSERT`、`UPDATE`、`DELETE` 权限的 `student_app` 账号。密码采用隐藏交互输入，只写入权限为 `0600` 的临时客户端配置并在退出时删除，不进入命令行或仓库。

上游 `ry_20260417.sql` 和 `quartz.sql` 均含 `DROP TABLE IF EXISTS`，因此脚本只会在数据库和两个应用账号全部不存在时导入。三者都存在时脚本进入只读验证路径；部分存在时立即停止。首次初始化中途失败时，只回滚本次新建的 `student_system` 和两个 `student_app` 本地账号，不接触其他数据库或账号。

导入顺序固定为：

1. `sql/ry_20260417.sql`：若依系统表、代码生成表和初始化数据；
2. `sql/quartz.sql`：Quartz 11 张表及物理外键。

基础 SQL 没有显式字符集或排序规则，因此继承数据库级配置。若依系统表没有声明物理外键，用户、角色、菜单等关系由关联表和业务代码维护；Quartz SQL 明确声明了物理外键。MariaDB 11.8 对脚本中的 InnoDB、`AUTO_INCREMENT`、`datetime`、`blob`、注释和复合外键语法均有对应实现，但本轮尚未实际导入，不能把兼容性标为通过。

项目按上游保留 MySQL Connector/J，而不是擅自替换驱动。MariaDB 提供 MySQL 客户端协议兼容性，但是否覆盖本项目使用路径必须通过真实启动和 CRUD 验证。若实测出现驱动差异，再评估 MariaDB Connector/J，不能在无证据时替换依赖。

## 5. Valkey 配置

Spring Boot 通过 `spring-boot-starter-data-redis` 使用 Lettuce 连接池。源码中的 `RedisCache` 被验证码、登录失败计数、JWT 登录态、在线用户、系统配置缓存等功能调用。Valkey 实现 Redis 协议，因此配置仍位于 `spring.data.redis`。

## 5.1 日志目录

Logback 使用 `${LOG_PATH:-logs}`：可通过 `LOG_PATH` 环境变量或同名 JVM 属性覆盖，未配置时写入启动工作目录的 `logs/`。Logback 会在首次写入时创建目录；也可预先执行 `mkdir -p logs`。该目录和 `*.log` 已被 `.gitignore` 排除，配置不依赖 Fedora 用户主目录，在 Windows 中同样可使用相对路径。Java 进程不应使用 sudo 启动。

宿主机验证命令：

```bash
valkey-cli -h 127.0.0.1 -p 6379 ping
```

若启用了密码，增加 `-a` 会把密码暴露在进程参数中；更安全的做法是先进入 `valkey-cli` 再交互执行 `AUTH`。本项目不修改 Valkey 全局监听或认证配置。

## 6. 构建、启动与接口验证

Maven 使用默认用户仓库 `~/.m2/repository`，不再通过 `-Dmaven.repo.local` 在项目内维护重复缓存。Fedora/Linux 推荐流程：

```bash
cp .env.example .env.local
chmod 600 .env.local
# 编辑 .env.local 后执行：
./scripts/check-env.sh
./scripts/build-backend.sh
./scripts/start-backend.sh
```

脚本由自身路径推导项目根目录，与调用时的工作目录无关；`LOG_PATH` 和 `RUOYI_PROFILE` 未显式配置时，会分别使用项目的 `logs/` 和 `data/uploadPath/`。后端以前台方式运行，使用 `Ctrl+C` 停止，不提供按名称批量终止 Java 进程的功能。

另开终端启动前端：

```bash
cd frontend && npm install
cd ..
./scripts/start-frontend.sh
```

Windows 对应命令为 `scripts\build-backend.cmd`、`scripts\start-backend.cmd` 和 `scripts\start-frontend.cmd`。Windows 环境变量从当前 PowerShell/CMD 会话继承，不读取 Bash 格式的 `.env.local`。

Vue3 开发服务器默认监听 3000 端口，访问地址为 `http://localhost:3000`。`.env.development` 将 Axios 基础路径设置为 `/dev-api`，Vite 把该前缀代理到 `VITE_PROXY_TARGET`，默认是 `http://localhost:8080`；代理时移除 `/dev-api`。修改端口可使用 `VITE_DEV_PORT` 或启动脚本后的 `--port` 参数。

首次宿主机安装已生成 npm lockfile v3。`frontend/node_modules` 实际占用 314 MB，生产输出 `frontend/dist` 为 7.0 MB，共享默认 npm 缓存 `~/.npm` 为 675 MB；项目中没有独立 npm 缓存。生产构建转换 2,542 个模块并成功完成。后续成员应使用 `npm ci` 严格按锁文件安装，不应删除或忽略 `package-lock.json`。

基础检查顺序为 `/captchaImage`、`POST /login`、`GET /getInfo`、`GET /getRouters`、用户/角色/菜单页面、`/v3/api-docs` 和 `/swagger-ui.html`。除登录、注册、验证码和文档端点外，其余接口需要 `Authorization: Bearer <token>`。

## 7. VS Code 的三个 JDK 概念

Java 扩展的语言服务器由扩展自身选择的 JDK 运行；`mvn -version` 显示 Maven 构建 JDK；后端调试进程则由 VS Code Java 启动配置和当前环境决定。三者不一定相同。共享配置不写个人路径，若后续需要 JDK 17，应在个人设置或当前终端设置 `JAVA_HOME`，再分别用 `Java: Configure Java Runtime`、`mvn -version` 和应用启动日志核对。

## 8. Maven 缓存整理记录

整理前默认仓库 `~/.m2/repository` 为 215 MB，项目 `.m2/repository` 为 123 MB。项目仓库共检查 740 份 SHA-1，零不匹配；193 个 JAR 均可解包。迁移前两个仓库有 1,310 个相同构件文件且零内容冲突，默认仓库缺少 170 个有效文件、约 5.7 MiB。

用户在宿主终端通过 `rsync --ignore-existing` 完成无覆盖迁移后，默认仓库为 221 MB。再次比对确认项目仓库的 1,480 个有效文件已全部存在于默认仓库，缺失 0、内容冲突 0。随后使用默认仓库执行 `mvn -o test` 与 `mvn -o clean package`，两次 Reactor Summary 均显示 7 个模块全部 `SUCCESS` 和 `BUILD SUCCESS`。经用户明确确认，项目 `.m2` 已删除，实际回收约 123 MB；默认仓库及各模块 `target/` 未删除。

## 9. 本轮受限项

- 当前执行环境禁止访问 systemd、Unix socket、TCP socket和 netlink，无法确认 MariaDB/Valkey 服务状态或端口监听。
- 当前 Codex 文件系统对用户主目录只读，不能代替用户把 5.7 MiB 缺失构件迁入默认 Maven 仓库，也不能在默认仓库完成离线构建；项目级仓库的既有构建已成功。
- npm 在线安装无响应，离线缓存又缺少 `@element-plus/icons-vue`，依赖安装和前端构建未完成。
- 当前工作区的 `.git/` 是只读空目录，Git 初始化和 remote 登记未完成。
- 课程 RAR 已使用系统现有 `unar` 安全提取；原文件副本和要求提取记录已保存到 `docs/reference/`。

这些限制影响验证结论，不影响已经完成的源码导入、静态分析、配置和文档初稿。
