## 4. 主要逻辑关系（基础表，无物理外键）

```text
sys_dept 1 ── N sys_user            (user.dept_id)
sys_dept 1 ── N sys_dept            (parent_id 自关联)
sys_user N ── N sys_role            (sys_user_role)
sys_role N ── N sys_menu            (sys_role_menu)
sys_role N ── N sys_dept            (sys_role_dept, 数据范围)
sys_user N ── N sys_post            (sys_user_post)
sys_dict_type 1 ── N sys_dict_data  (dict_type 字符串逻辑关联)
sys_notice 1 ── N sys_notice_read   (notice_id)
gen_table 1 ── N gen_table_column   (table_id)
```

**约束事实：**

- 若依基础表在 SQL 中没有声明 `FOREIGN KEY`；关系由 MyBatis/Service 维护。
- `sys_notice_read` 有唯一键 `(user_id, notice_id)`（源码可验证）。
- `sys_user_role`、`sys_role_menu`、`sys_role_dept`、`sys_user_post` 使用复合主键，防止重复关联。
- 用户/角色/菜单表是认证授权基础，不是学生业务实体。

## 5. Quartz 表与物理外键

SQL 定义 11 张 `QRTZ_*` 表：

`QRTZ_JOB_DETAILS`、`QRTZ_TRIGGERS`、`QRTZ_SIMPLE_TRIGGERS`、`QRTZ_CRON_TRIGGERS`、`QRTZ_BLOB_TRIGGERS`、`QRTZ_CALENDARS`、`QRTZ_PAUSED_TRIGGER_GRPS`、`QRTZ_FIRED_TRIGGERS`、`QRTZ_SCHEDULER_STATE`、`QRTZ_LOCKS`、`QRTZ_SIMPROP_TRIGGERS`。

源码 SQL 中存在物理外键（示例）：

- `QRTZ_TRIGGERS(sched_name,job_name,job_group)` → `QRTZ_JOB_DETAILS`
- `QRTZ_SIMPLE_TRIGGERS` / `QRTZ_CRON_TRIGGERS` / `QRTZ_BLOB_TRIGGERS` / `QRTZ_SIMPROP_TRIGGERS` → `QRTZ_TRIGGERS`

这些外键只属于 Quartz 调度子系统，不应拿来推断学生业务表也有物理外键。

## 7. 设计中的主键/命名约束

- 课程要求新增业务表使用 `id INT AUTO_INCREMENT` 主键；
- 若依基础表使用 `bigint` 主键，不能强行改成 int；
- 学生业务表建议 `id INT AUTO_INCREMENT`，业务唯一键用 `UNIQUE`（如学号、考试×班级×科目）；
- 业务表与 `sys_user` 的逻辑关联通过账号绑定表/业务外键 ID 实现，不能把 `sys_user.user_id` 直接当学生 ID；
- 逻辑关联不默认建物理外键，具体由数据库设计阶段评审决定。
