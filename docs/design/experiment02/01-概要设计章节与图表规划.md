## 3. 下一阶段总体架构图绘制建议

### 3.1 推荐主图（FIG-D1）

```text
[浏览器]
  -> [Vue3 SPA: Element Plus + Pinia]
  -> [Vite dev proxy /dev-api 或生产静态资源]
  -> [Spring Security + JWT Filter]
  -> [Controller 层]
  -> [Service 层：事务/状态机/数据范围]
  -> [MyBatis Mapper + XML]
  -> [MariaDB 11.8: student_system]
  -> [Valkey: captcha/login/cache]
  -> [Springdoc OpenAPI]
```

- 左侧显示浏览器/前端，右侧显示后端/数据；
- 用不同颜色区分 **现有若依基础** 与 **待新建 student 业务模块**；
- 图中明确 `Valkey` 只存登录/缓存，不存成绩真值；
- 不要把 `Quartz` 画成成绩业务主链；
- 不画任课教师/任教关系。

### 3.2 后端模块图（FIG-D2）

```text
ruoyi-admin
  ├─ ruoyi-framework
  ├─ ruoyi-quartz
  ├─ ruoyi-generator
  └─ ruoyi-student（建议新增，待评审）
       ├─ student-controller
       ├─ student-service
       ├─ student-mapper
       └─ student-domain
ruoyi-framework -> ruoyi-system -> ruoyi-common
```

> `ruoyi-student` 是建议，不是现有模块；在正式设计评审前不得创建。

### 3.3 数据库 ER 图

- **FIG-D5**：现有若依 20 张系统/生成表 + 11 张 Quartz 表的逻辑关系；基础表无物理外键，Quartz 有物理外键。
- **FIG-D6**：实验一 17 DR + ENT-08；展示学生、班级、班主任任职、考试、任务、成绩、发布、审计、P1 复核。
- 图中不把 `sys_user` 直接连成“学生”，而通过“账号-档案绑定”关联。
- 不把 `sys_dept` 直接当行政班。

### 3.4 时序/活动图

- **登录时序**：验证码→登录→Token→getInfo→getRouters；
- **用户查询时序**：页面 API→Controller→Service→Mapper→DB；
- **成绩主流程**：任务生成→班主任录入→校验→提交→教务审核→发布→学生查询；
- **异常流程**：退回重提、撤回/更正（复用实验一 FIG-07A～D 的结论，不重画需求模型）。

## 4. 每模块正式设计的写法

每个学生业务模块至少写：

1. 模块目标与边界；
2. 参与角色/数据范围；
3. Controller 接口表（方法/路径/权限/请求/响应/错误码）；
4. Service 事务/状态机/校验；
5. Mapper/表/索引/唯一键；
6. 关联 FR/BR/DR/AC；
7. 异常与审计；
8. 前端页面/路由/按钮权限；
9. 待确认项。
