# 01 若依后端模块与依赖分析

> 依据：根 `pom.xml`、各模块 `pom.xml`、`src/main/java` 真实类、Mapper XML。  
> 版本：RuoYi 3.9.2 / Spring Boot 3.5.16 / Java 编译目标 17。

## 1. Maven 模块总览

| 模块 | 实际目录 | 主要职责 | 主要依赖 | 关键类/配置 |
| --- | --- | --- | --- | --- |
| `ruoyi-admin` | `ruoyi-admin/` | Web 启动入口、Controller、Springdoc、运行配置 | framework、quartz、generator、MySQL Connector/J | `com.ruoyi.RuoYiApplication`、`web/controller/**`、`application.yml` |
| `ruoyi-framework` | `ruoyi-framework/` | Security/JWT、Druid、Redis、MyBatis、AOP、异常处理 | system、common、Web/AOP/Druid/Kaptcha | `config/SecurityConfig.java`、`security/filter/JwtAuthenticationTokenFilter.java`、`web/service/TokenService` |

## 2. 模块依赖关系

源码依赖（按 POM 的直接依赖整理）：

```text
ruoyi-admin
  ├── ruoyi-framework
  ├── ruoyi-quartz
  ├── ruoyi-generator
  └── MySQL Connector/J
ruoyi-framework
  ├── ruoyi-system
  └── ruoyi-common
ruoyi-system
  └── ruoyi-common
ruoyi-quartz
  ├── ruoyi-common
  └── (Quartz)
ruoyi-generator
  ├── ruoyi-common
  └── (Druid)
```

**设计含义：**

- 认证、异常、数据源、缓存等横切能力在 framework/common；
- 系统管理领域在 system；
- admin 只做 Web 入口和装配，不承载系统管理领域实现；
- 学生业务不应塞进 `ruoyi-common` 或 `ruoyi-framework`；建议新增独立业务模块/包（下一阶段决策）。

## 4. 真实用户管理调用链

### 4.1 列表请求

```text
GET /system/user/list?pageNum=1&pageSize=10
  -> SysUserController.list(SysUser)
  -> ISysUserService.selectUserList(SysUser)
  -> SysUserServiceImpl.selectUserList(...)
  -> SysUserMapper.selectUserList(...)
  -> resources/mapper/system/SysUserMapper.xml
  -> MariaDB: sys_user + sys_dept 等
  -> TableDataInfo(rows,total)
```

| 层 | 真实文件 | 关键方法/注解 |
| --- | --- | --- |
| Controller | `ruoyi-admin/src/main/java/com/ruoyi/web/controller/system/SysUserController.java` | `@RequestMapping("/system/user")`、`@GetMapping("/list")`、`@PreAuthorize("@ss.hasPermi('system:user:list')")` |
| Service 接口 | `ruoyi-system/src/main/java/com/ruoyi/system/service/ISysUserService.java` | `selectUserList` |
| Service 实现 | `ruoyi-system/src/main/java/com/ruoyi/system/service/impl/SysUserServiceImpl.java` | `@DataScope(deptAlias="d", userAlias="u")` |
| Mapper | `ruoyi-system/src/main/java/com/ruoyi/system/mapper/SysUserMapper.java` | `selectUserList` |
| Mapper XML | `ruoyi-system/src/main/resources/mapper/system/SysUserMapper.xml` | 用户/部门 SQL |
| 分页 | `ruoyi-common` / `BaseController` | `startPage()`、PageHelper |
| 返回 | `com.ruoyi.common.core.domain.AjaxResult` / `TableDataInfo` | 统一响应 |

### 4.2 登录/权限链

```text
GET /captchaImage -> CaptchaController
POST /login -> SysLoginController.login -> SysLoginService -> TokenService -> Valkey LoginUser
GET /getInfo -> SysLoginController.getInfo -> SysPermissionService -> 用户/角色/菜单
GET /getRouters -> SysLoginController.getRouters -> ISysMenuService -> 动态菜单
```

- `SysLoginController`：`ruoyi-admin/src/main/java/com/ruoyi/web/controller/system/SysLoginController.java`
- `SysLoginService`：`ruoyi-framework/src/main/java/com/ruoyi/framework/web/service/SysLoginService.java`
- `TokenService`：`ruoyi-framework/src/main/java/com/ruoyi/framework/web/service/TokenService.java`
- `SysPermissionService`：`ruoyi-framework/src/main/java/com/ruoyi/framework/web/service/SysPermissionService.java`
- JWT filter：`ruoyi-framework/src/main/java/com/ruoyi/framework/security/filter/JwtAuthenticationTokenFilter.java`

## 5. 鉴权与数据范围

- 方法级权限：`@PreAuthorize("@ss.hasPermi('system:user:list')")`；
- 数据范围：`@DataScope` 在 Service 查询上追加部门/用户范围条件；
- 登录态：JWT 放 `Authorization: Bearer ...`，服务端登录用户存 Valkey；
- 放行：`/login`、`/register`、`/captchaImage`、静态资源、Swagger、Druid；
- 其他请求需认证；
- 当前源码没有学生业务权限字符串；建议未来使用 `business:student:*`、`business:score:*` 等独立命名空间，不能复用 `system:*` 糊在一起。

## 6. 复用价值与限制

### 可直接复用

| 能力 | 证据 | 用途 |
| --- | --- | --- |
| 登录/验证码/JWT | `SysLoginController`、`SecurityConfig` | 四类角色统一入口 |
| 用户/角色/菜单/按钮 | `SysUserController`、`SysRoleController`、`SysMenuController` | 基础 RBAC |
| 部门/岗位/字典/参数 | `SysDeptController`、`SysPostController`、字典/参数服务 | 组织辅助、字典显示 |
| 操作/登录日志 | `SysOperlogController`、`SysLogininforController` | 系统审计 |
| 代码生成 | `GenController` + `resources/vm` | 后续生成 CRUD 骨架，禁生成状态机 |
| OpenAPI | Springdoc 2.9.0 | 接口文档 |

### 需要适配/扩展

| 点 | 原因 |
| --- | --- |
| 业务角色→若依角色/账号绑定 | 若依只有 `sys_user/sys_role`；学生/班主任业务档案尚未建模 |
| 数据范围 | `@DataScope` 默认部门树，不能直接表达“本班/本人/已发布” |
| 业务审计 | `sys_oper_log` 是操作日志，不能替代成绩变更前后值/版本 |
| 班级/年级 | `sys_dept` 只是内部组织，不应直接等同行政班 |
| 业务菜单 | 需在 `sys_menu` 增加学生业务菜单和 `business:*` 权限 |

### 不应复用/不应混淆

- 不把数据库、Redis、Controller/Service 当作业务角色；
- 不把 `sys_user` 直接当学生档案；
- 不在 `ruoyi-common` 中加入学生业务实体；
- 不恢复任课教师角色/任教关系。

## 7. 真实缺失

当前 `ruoyi-admin` Controller 中只有系统、监控、工具和测试接口；**没有学生、班级、班主任、考试、成绩、发布、查询、统计、业务审计 Controller**。  
`ruoyi-system` 中没有对应学生业务 Service/Mapper/Domain。  
因此实验一 SRS 的业务需求均属“待设计/待实现”，不是现有若依功能。
