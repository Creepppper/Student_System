# 02 架构决策记录：学生业务模块组织

> 状态：**推荐方案，待小组评审；未批准、未实施**。  
> 本阶段不创建 `ruoyi-student`、不修改 POM、不新增代码。

## ADR-001 学生业务放在哪里？

### 背景

当前有 6 个真实 Maven 模块：

`ruoyi-admin`、`ruoyi-framework`、`ruoyi-system`、`ruoyi-common`、`ruoyi-quartz`、`ruoyi-generator`。

学生业务需要新增组织、学生、班主任、考试、成绩、发布、查询、统计、审计和 P1 扩展。若全部塞入 `ruoyi-system`，会混入大量业务实体和状态机；若放入 `ruoyi-common`/`ruoyi-framework`，会污染公共/框架层。

### 选项 A：新增 `ruoyi-student`

```text
ruoyi-student/
  domain/
  mapper/
  service/
  service/impl/
  resources/mapper/student/
```

- `ruoyi-student` 依赖 `ruoyi-common`，必要时依赖 `ruoyi-system`（账号/角色类型）；
- `ruoyi-admin` 依赖 `ruoyi-student`；
- Controller 放 `ruoyi-admin` 的 `com.ruoyi.web.controller.business`；
- `ruoyi-system`/`ruoyi-framework` 不依赖学生模块；
- Mapper XML 放 `mapper/student/`，现有 `classpath*:mapper/**/*Mapper.xml` 可覆盖；
- Spring Boot 扫描 `com.ruoyi.student`（启动类在 `com.ruoyi` 根包）；
- 事务复用现有 DataSourceTransactionManager。

**优点：** 边界清晰、便于小组分工、P1 扩展不污染系统模块。  
**缺点：** 新增模块、根 POM/admin 依赖、Mapper 扫描/类型别名需启动验证。

### 选项 B：扩展 `ruoyi-system`

在 `ruoyi-system` 增加 `com.ruoyi.system.student` 包。

**优点：** 不新增 Maven 模块，构建配置改动少，直接使用 SysUser。  
**缺点：** 系统管理与学生业务耦合；模块体积大；多人协作冲突；长期维护/P1 扩展差。

### 决策

**推荐选项 A**，理由：与若依的“基础能力/业务模块”分层一致，符合“不要把学生业务实体塞进 ruoyi-common”的约束。  
但标记为 **待小组评审**：新增模块会增加构建复杂度和 Mapper 扫描验证成本，课程演示是否值得需确认。

### 影响

- 根 POM 新增 `<module>ruoyi-student</module>`（**未执行**）；
- `ruoyi-admin/pom.xml` 新增依赖（**未执行**）；
- Mapper 扫描/`typeAliasesPackage` 需启动验证；
- 不改变若依系统模块功能；
- 当前 6 模块统计不变。

## ADR-002 Controller 放在哪？

**推荐：** `ruoyi-admin/src/main/java/com/ruoyi/web/controller/business/`。  
**理由：** Controller 属于 Web 接入；admin 已有 Spring MVC/安全/统一响应；业务模块无需引入 Web 依赖。  
**备选：** 放 `ruoyi-student` controller 包，需增加 Web 依赖；不推荐。

## ADR-003 数据权限如何实现？

**不采用：** 仅依赖 `@DataScope` 默认部门树。  
**采用：**

1. `@PreAuthorize` 做功能权限；
2. Service 读取当前登录用户和业务绑定；
3. 班主任按当前有效任职班级集合过滤；
4. 学生按绑定学生 ID + 发布状态过滤；
5. 教务 `SCOPE_ALL`；
6. 系统管理员拒绝成绩明细。

`@DataScope` 可继续用于若依部门级基础能力，但不能替代本班/本人。

## ADR-004 业务审计如何实现？

**不采用：** 仅用 `sys_oper_log`。  
**采用：** 独立业务审计表/记录，包含对象类型/ID/版本、前后值、原因、操作人/角色、时间；与业务同事务；不可修改/删除。  
`sys_oper_log` 仍保留系统操作日志，但不能替代成绩审计。

## ADR-005 P1 边界

P1 复核/导入/趋势/对比不在 P0 主链路中：单独权限/菜单/接口/表，不改变 P0 状态机；不把 P1 功能写成已实现。
