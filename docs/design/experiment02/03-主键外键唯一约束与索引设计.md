## 2. 唯一键

### stu_year

### stu_term

- `uk_stu_term_no` (`year_id`, `term_no`)：同一学年学期序号唯一
- `uk_stu_term_name` (`year_id`, `term_name`)：同一学年学期名称唯一

### stu_grade

- `uk_stu_grade_code` (`grade_code`)：年级代码唯一

### stu_class

### stu_student

### stu_head_teacher_assignment

## 5. 逻辑关联（不建物理 FK）

- `stu_account_binding.user_id` → `sys_user.user_id`：类型 BIGINT；不建物理 FK，服务层校验账号存在、未被停用、类型匹配。
- `stu_audit_log.object_id`：多态引用（task/score/publication/version），不建物理 FK。
- `stu_publication.current_version_id`：为避免循环创建，表建完后用 `ALTER TABLE` 增加物理 FK；也可降级为逻辑关联，需评审。
- 若依基础表之间的关联全部为逻辑关联，不改原表。

## 6. 外键策略

**混合策略：**

1. 学生业务内部的稳定父子关系使用物理 FK（`RESTRICT`），保护成绩/发布/版本完整性；
2. `sys_user` 绑定不建物理 FK（若依原生表、软删除/迁移风险），但字段类型必须 BIGINT，服务层强校验；
3. 多态审计不建 FK；
4. 历史/发布版本禁止级联删除，不使用 `CASCADE`；
5. 时间区间重叠不能由普通 UNIQUE 完整表达，需生成列 + 事务 + 索引 + Service 校验。

## 7. 时间区间/当前唯一

- `stu_year.current_slot`、`stu_student_class.active_student_key`、`stu_head_teacher_assignment.active_class_key`、`stu_account_binding.active_user_key/active_profile_key` 使用生成列 + UNIQUE，表达“最多一个当前”。
- 生成列在 MySQL 8 与 MariaDB 11.8 可用；生成列表达式必须保持确定性。
- 历史区间不重叠：普通 UNIQUE 不能表达 `[from,to)` 不重叠；由事务锁（学生/班级行锁）+ Service 校验 + 起止索引共同保证。
- 结束当前关系时，必须同一事务关闭旧记录并插入新记录；禁止只更新覆盖。

## 8. 索引原则

- 所有 FK 列显式索引；业务唯一键优先于普通索引；
- 任务：`(exam_id,class_id,subject_id)` UK；成绩：`(task_id,student_id)` UK；
- 发布：`(exam_id,class_id)` UK；版本：`(publication_id,version_no)` UK；
- 审计：`(object_type,object_id,occurred_at)`、`(operator_user_id,occurred_at)`；
- 不建“所有列都加索引”的反模式；导出/统计查询上线前用 `EXPLAIN` 验证。
