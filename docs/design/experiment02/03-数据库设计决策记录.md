# 03 数据库设计决策记录（ADR）

## ADR-DB-001 表名前缀：统一 `stu_`

**选项：**

- `stu_*`：短、区分 `sys_*`/`QRTZ_*`/`gen_*`；课程示例常用；
- `biz_*`：通用，但学生业务语义弱；
- `edu_*`：教育域准确，但与当前命名风格不一致。

**决策：** 推荐 `stu_*`，全部 P0/P1 一致；`stu_` 表示业务域，不表示只存学生。  
**状态：** 推荐，待评审。

## ADR-DB-002 主键：`id INT AUTO_INCREMENT`

- 新建业务主表统一 `id INT NOT NULL AUTO_INCREMENT PRIMARY KEY`；
- 学号/工号/考试编码是业务唯一键（UK + VARCHAR），不是自增主键；
- `sys_user.user_id` 保持 `BIGINT`，不改原表；
- 绑定表 `user_id` 用 `BIGINT` 兼容。

**理由：** 课程要求 + 避免学号变更破坏外键 + 业务唯一性独立。  
**状态：** 推荐，待评审。

## ADR-DB-003 外键：混合策略

**背景：** 若依基础表无物理 FK；Quartz 有 5 个 FK。

**决策：**

1. 学生业务内部稳定父子关系使用物理 FK（`ON DELETE RESTRICT`）；
2. `sys_user` 绑定使用逻辑关联 + 服务层校验（不建物理 FK）；
3. `stu_audit_log` 多态引用不建 FK；
4. `stu_publication.current_version_id` 因循环依赖，建表后 `ALTER` 补 FK；可选降级逻辑；
5. 不因若依基础表无 FK 就禁止所有新 FK；也不对所有表盲目加 FK。

**状态：** 推荐，待评审；需在测试库验证循环 FK/迁移顺序。

## ADR-DB-004 发布对象拆三表

`DR-PUB-001` 逻辑上是一个发布对象，物理拆：

- `stu_publication`：当前状态/当前版本；
- `stu_publication_version`：不可变版本头；
- `stu_publication_version_detail`：不可变成绩明细。

**理由：** 当前可见状态与历史版本分离；撤回/更正不覆盖历史；版本可审计。  
**代价：** 表数增加、发布事务写入更多行；对课程规模可接受。  
**状态：** 推荐，待评审。

## ADR-DB-005 账号—档案绑定

- 单独 `stu_account_binding`，不把账号字段塞学生表；
- `user_id BIGINT` + 逻辑 FK；
- `profile_type` + 二选一档案字段 + CHECK；
- 生成列唯一槽位保证每类一个有效绑定；
- 系统管理员不能凭 `ALL_PERMISSION` 看成绩明细，Service 显式拒绝。

**状态：** 推荐，待评审。

## ADR-DB-006 时间区间与当前唯一

- `is_current` + 生成列唯一键表达“最多一个当前”；
- 历史区间不重叠不能靠普通 UNIQUE 完整表达；
- 用事务行锁 + Service 校验 + 起止索引 + 当前唯一键共同保证；
- 转班/换班主任必须关闭旧记录 + 插入新记录，不覆盖。

**状态：** 推荐；具体隔离级别/锁策略在实现阶段验证。

## ADR-DB-007 成绩三态

- `SCORE_NORMAL` + `DECIMAL(6,1)` 非空；
- `SCORE_ABSENT`/`SCORE_NOT_ENTERED` + NULL；
- 0.0 是正常成绩；
- DB CHECK + Service 双重校验 0.5；
- 不用 FLOAT/DOUBLE。

**状态：** 必须，来自 SRS；数据库设计已落实。

## ADR-DB-008 总分/排名

**P0 推荐：不建总分/排名表，按当前发布版本明细查询计算。**

- 避免成绩修改/撤回/更正导致汇总表失真；
- 排名只在同一考试/班级/口径内；
- 缺考不进入有效人数/分母；
- 缓存只读，不作为真值；按 publication_version_id 失效；
- 若未来物化，必须绑定 publication_version_id，不能覆盖历史。

**状态：** 推荐，待评审；性能数据不足，保留物化选项。

## ADR-DB-010 审计存储

- 独立 `stu_audit_log`，不只依赖 `sys_oper_log`；
- `before_data/after_data` 用 LONGTEXT（应用 JSON），避免 MariaDB JSON 别名差异；
- 同事务、只插入、前后值/原因/操作人/角色/版本；
- 多态 object_id，不建 FK；
- 不存密码/Token/完整敏感个人信息。

**状态：** 推荐，待评审。
