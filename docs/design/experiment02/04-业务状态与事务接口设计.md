# 04 业务状态与事务接口设计

> 依据 SRS 3.7～3.9、4.6～4.11、5.5～5.7；不新增业务状态代码。  
> 这是接口层设计，不实现 Service。

## 1. 四套状态

| 对象 | 字段 | 合法状态 |
| --- | --- | --- |
| 考试 | `stu_exam.status` | `EXAM_DRAFT`、`EXAM_OPEN`、`EXAM_CLOSED`、`EXAM_ARCHIVED` |
| 任务 | `stu_score_task.task_status` | `TASK_DRAFT`、`TASK_SUBMITTED`、`TASK_APPROVED`、`TASK_RETURNED` |
| 发布 | `stu_publication.publication_status` | `PUB_UNPUBLISHED`、`PUB_PUBLISHED`、`PUB_WITHDRAWN` |
| 成绩 | `stu_score.score_status` | `SCORE_NORMAL`、`SCORE_ABSENT`、`SCORE_NOT_ENTERED` |

- 不合并状态；
- `TASK_APPROVED` 不代表可见；
- `PUB_WITHDRAWN` 不删除历史。

## 2. 状态动作表

| API | 动作 | 前置 | 后置 | 事务 |
| --- | --- | --- | --- | --- |
| API-SCORE-004 | 保存草稿 | 任务 DRAFT/RETURNED；EXAM_OPEN；当前班主任 | 草稿；任务不变 | 成绩+审计 |
| API-SCORE-005 | 提交 | DRAFT/RETURNED；无未录入；version | SUBMITTED；锁定 | 任务+审计 |
| API-SCORE-007 | 审核通过 | SUBMITTED；非提交人 | APPROVED | 任务+审计 |
| API-SCORE-007 | 退回 | SUBMITTED；原因 | RETURNED | 任务+审计 |
| API-EXAM-005 | 开考 | DRAFT | OPEN | 考试+审计 |
| API-EXAM-005 | 结束 | OPEN | CLOSED | 考试+审计 |
| API-EXAM-005 | 归档 | CLOSED | ARCHIVED | 考试+审计 |
| API-PUB-002 | 发布 | 全部 APPROVED、无未录入、至少一科 | PUBLISHED；版本+1 | 发布+版本+明细+审计 |
| API-PUB-004 | 撤回 | PUBLISHED | WITHDRAWN；历史保留 | 发布+审计 |
| API-PUB-005 | 重新发布 | WITHDRAWN；任务仍 APPROVED | PUBLISHED；版本+1 | 发布+版本+审计 |
| API-PUB-006 | 更正 | PUBLISHED；原因；非自审 | PUBLISHED；新版本 | 成绩+版本+明细+审计 |

## 3. 成绩三态/精度

- NORMAL：`score_value` 非空，0～满分，0.5；
- ABSENT：NULL；
- NOT_ENTERED：NULL；提交时阻止；
- 0.0 是 NORMAL；
- 完整总分才计算/排名；ABSENT 不进入有效人数；
- DB CHECK + Service 两层；精确满分按任务快照；
- 任何非法值返回 400 `INVALID_SCORE`，不自动转 0/缺考。

## 4. 发布/版本事务

发布必须在**同一数据库事务**：

1. 锁相关任务/成绩；
2. 校验状态、无未录入、至少一科；
3. 插入/更新 publication；
4. 插入不可变 version；
5. 插入全量 version_detail；
6. 更新 current_version/status；
7. 插入 audit；
8. commit。

- 失败全回滚；
- 版本明细不引用可变 score 作为历史真值；
- 撤回只改当前状态；
- 更正新版本，不 UPDATE 旧版本/旧明细；
- 发布后查询使用当前 `PUB_PUBLISHED` 版本。

## 5. 并发与幂等

| 操作 | 幂等键 | 版本 | 冲突 |
| --- | --- | --- | --- |
| 保存草稿 | 可选 | 必须 | 409 `VERSION_CONFLICT` |
| 提交 | 必须 | 必须 | 409 重复/版本 |
| 审核 | 必须 | 必须 | 409 重复/状态 |
| 发布 | 必须 | 必须 | 409 重复/状态 |
| 撤回 | 必须 | 必须 | 409 状态 |
| 重新发布 | 必须 | 必须 | 409 状态/版本 |
| 更正 | 必须 | 必须 | 409 版本/状态 |
| 任务生成 | 必须 | N/A | 409 重复 |

- 幂等键同体回放首次结果；不同体拒绝；
- 数据库唯一键是最后防线；
- 任务生成按考试×班级×科目唯一，不重复插入；
- 并发更正锁 publication/version 行，失败 409，不覆盖。

## 6. 事务外的派生

- 总分/排名：从当前发布版本明细计算；可异步/缓存，但版本变化必须失效；
- 通知：事务提交后异步；
- 大屏/报表缓存：不作为成绩真值；
- 不先改成绩再异步审计；审计失败业务回滚。

## 7. 对接口的硬要求

- Controller 不写状态机；
- Service 接收 `version`，校验影响行数；
- 不允许 `PUT` 任意字段改状态；
- 不允许“已审核”一个布尔字段代替 `TASK_*`/`PUB_*`；
- 系统管理员不能借通用权限跳过状态/职责校验；
- 返回 409 时前端刷新，不自动重试覆盖。
