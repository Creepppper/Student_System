# 04 接口设计决策记录（ADR）

> 本阶段工作假设：19 张 P0 表、`stu_` 前缀、独立 `ruoyi-student` 推荐、Controller 放 `ruoyi-admin`、绑定表、P1 独立、多班按单班、`current_version_id` 逻辑关联、管理员阻断成绩。  
> 这些都是**待评审工作假设**，不是小组已批准。

## ADR-API-001 URL 前缀：`/business/**`

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| `/student/**` | 直观 | 容易误解为只服务学生；教务/班主任接口也在此 | 不推荐 |
| `/school/**` | 学校域 | 与若依现有 `/system/**` 风格不一致；过宽 | 不推荐 |
| `/business/**` | 明确业务域；与 `/system/**`/`/monitor/**` 区分；便于权限 `business:*` | “business”较泛 | **推荐** |

**决策：** 新业务 API 全部 `/business/**`；现有若依保持 `/system`、`/monitor`、`/tool`、`/common`。不混用 `/student`、`/school`。

## ADR-API-002 接口数量与粒度

- P0：**68 个操作、53 条路径**；按资源 CRUD + 业务动作设计；
- 一条 FR 可对应多个 API，多个 FR 可共享查询接口；
- 不为“一个 FR 一个接口”强行拆分；
- P1：11 个独立操作，不与 P0 混文件；
- **API 状态全部规划，未实现**。

## ADR-API-003 复用现有认证 vs 新登录

- 登录/验证码/登出/`getInfo`/`getRouters` **直接复用**若依；
- 新增 `/business/me/identity` 只返回业务身份/绑定/范围，不替代登录；
- 不新建账号表、不修改 `sys_user`；
- 系统管理员账号管理仍用现有 `/system/user`；
- 学生档案与账号通过 `stu_account_binding`；学生身份取自会话绑定，不信任客户端 studentId。

## ADR-API-004 响应格式

- 复用 `AjaxResult{code,msg,data}` 与 `TableDataInfo{total,rows,code,msg}`；
- 成功 HTTP 200 + body 200；创建不强制 201；
- 业务错误码使用 `data.errorCode`（拟新增），不新增顶层字段；
- 错误 HTTP 400/401/403/404/409/500；
- 前端 `request.js` 继续处理 401/500/601；
- **现有若依没有 `data.errorCode` 约定**，这是业务新增。

## ADR-API-005 成绩/时间/版本序列化

- 成绩/线：JSON number，服务端 `DECIMAL(6,1)`，0.5 步长；
- 时间：`yyyy-MM-dd HH:mm:ss`；日期 `yyyy-MM-dd`；
- 布尔：true/false；
- 枚举：SRS 大写代码；
- `version` 必传（更新/状态/发布/更正）；冲突 409；
- 不把成绩序列化为字符串；不用 float 计算。

## ADR-API-006 幂等

- 提交/审核/发布/撤回/重发/更正/导入要求 `Idempotency-Key`；
- 同键同体回放；不同体拒绝；
- 数据库唯一键是最后防线；
- 前端防重不是安全边界。

## ADR-API-007 发布版本

- `POST /business/publications` 发布；`POST .../withdraw` 撤回；`POST .../republish` 重发；`POST .../corrections` 更正；
- 发布/撤回/更正均单事务；
- 本阶段假设 `publication.current_version_id` 为**逻辑关联**，Service 校验版本归属；第三阶段 SQL 曾提供后加物理 FK 方案，需评审二选一；
- 学生只读当前 `PUB_PUBLISHED` 版本。

## ADR-API-008 数据权限

- `@PreAuthorize` 功能权限 + Service 业务范围；
- 学生：当前有效绑定，SELF；
- 班主任：当前有效任职班级，CLASS；
- 教务：ALL；
- 系统管理员：账号/系统/脱敏审计；成绩明细 D*；
- 若依 `ALL_PERMISSION` 可绕过普通权限，Service 必须显式拒绝管理员；
- `@DataScope` 不替代本班/本人。

## ADR-API-009 多班班主任

- P0 按单班查询/统计；不混合平均；
- 合并统计列为 P1/待评审；
- 任务第一责任人是创建快照，换班不改历史；
- 不在 P0 实现跨班总排名。

## ADR-API-010 P1 边界

- P1 文件独立，不进入 P0 退出条件；
- 复核/导入导出/趋势/对比；
- 复核更正调用 P0 更正；
- 学生无班级对比权限；
- P1 状态/时限/通知待评审。
