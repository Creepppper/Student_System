# 04 请求响应与错误码规范

> 第一部分是**现有若依真实响应**；第二部分是**拟新增业务规范**，不能混称为现行实现。

## 1. 现有若依真实响应（源码核实）

`AjaxResult`（`ruoyi-common/.../AjaxResult.java`）：

```json
{"code": 200, "msg": "操作成功", "data": {}}
```

- `code`、`msg` 必有；`data` 可缺省；
- `AjaxResult.success()` 的 code 为 200；`error()` 默认 500；`warn()` 为 601；
- `TableDataInfo`（分页）：`{"total": 0, "rows": [], "code": 200, "msg": "查询成功"}`；
- 现有 HTTP 状态码常量包含 400/401/403/404/405/409/500 等（`HttpStatus`）；
- `GlobalExceptionHandler` 对 `AccessDeniedException` 返回 403“没有权限”；
- 前端 `request.js` 根据 `res.code` 处理 401/500/601；
- 后端未运行，以上为源码级；**没有运行时响应样本**。

## 2. 业务 API 统一响应（拟新增）

### 2.1 单对象/操作

沿用 `AjaxResult`：

```json
{"code": 200, "msg": "操作成功", "data": {"id": 1}}
```

- 成功 HTTP 200，body code 200；
- 创建不强制 HTTP 201；沿用若依 200，避免前端差异；
- `data` 的具体 Schema 在 OpenAPI `x-data-schema` / `components.schemas` 中。

### 2.2 分页

沿用 `TableDataInfo`：

```json
{"total": 42, "rows": [], "code": 200, "msg": "查询成功"}
```

- 请求参数 `pageNum`（≥1）、`pageSize`（1～100）；
- 排序 `orderByColumn` 必须服务端白名单映射，禁止拼接原样 SQL；
- 默认排序由 Service 固定（如 `id desc`）。

### 2.3 失败

```json
{
  "code": 409,
  "msg": "成绩已被他人修改，请刷新后重试",
  "data": {
    "errorCode": "VERSION_CONFLICT",
    "details": {"expected": 3, "actual": 4},
    "traceId": "trace-demo-001"
  }
}
```

- `code` 沿用现有数值语义：400/401/403/404/409/500；
- **新增 `data.errorCode` 字符串**用于前端分支/测试；不修改 `AjaxResult` 顶级字段；
- 不把 `errorCode` 说成现有若依已支持。

## 3. 错误码/状态设计（拟新增）

| HTTP | 顶层 code | data.errorCode（拟新增） | 场景 |
| ---: | ---: | --- | --- |
| 400 | 400 | `VALIDATION_ERROR` | 字段缺失/类型/长度/0.5/枚举 |
| 400 | 400 | `INVALID_SCORE` | 负分/超满分/缺考带分/未录入带分 |
| 401 | 401 | `UNAUTHORIZED` | 未登录/Token 失效 |
| 403 | 403 | `FORBIDDEN` | 功能权限不足 |
| 403 | 403 | `SCOPE_DENIED` | 非本班/非本人/非授权班级 |
| 403 | 403 | `ADMIN_SCORE_FORBIDDEN` | 系统管理员不得看成绩明细 |
| 404 | 404 | `NOT_FOUND` | 资源不存在 |
| 409 | 409 | `STATE_CONFLICT` | 状态不允许（如未审核就发布） |
| 409 | 409 | `VERSION_CONFLICT` | 乐观锁失败 |
| 409 | 409 | `DUPLICATE_SUBMIT` | 重复提交/重复审核/重复发布 |
| 409 | 409 | `PUBLICATION_WITHDRAWN` | 已撤回仍按旧版本查询/更正 |
| 409 | 409 | `IDEMPOTENCY_REPLAY` | 同幂等键不同请求体 |
| 500 | 500 | `INTERNAL_ERROR` | 未预期异常 |

- 客户端应按 HTTP 状态 + `data.errorCode` 分支；
- 前端只显示 `msg`，测试断言 code/errorCode；
- **错误响应不返回 SQL、堆栈、密码、Token、成绩前后值**。

## 4. 字段与序列化

| 项 | 规范 |
| --- | --- |
| 时间 | `yyyy-MM-dd HH:mm:ss`（与 `BaseEntity` 的 `@JsonFormat` 一致） |
| 日期 | `yyyy-MM-dd` |
| 时区 | `Asia/Shanghai`（业务显示）；跨时区部署需统一配置，属待确认 |
| 成绩 | JSON number；服务端 `DECIMAL(6,1)`；0.5 步长；不用 FLOAT/字符串 |
| 满分/线 | number；`multipleOf: 0.5` |
| 布尔 | true/false，不用 0/1/T/F |
| 枚举 | 大写代码（`SCORE_NORMAL` 等）；未知值 400 |
| 版本 | `version` 整数，必须回传；`0` 为初始版本 |
| ID | JSON integer；`user_id` 为 int64，业务 id 为 int32 |
| 空值 | 明确 `null`；未录入/缺考不得用 0 代替 |
| 文件 | P1 导入/导出使用 `multipart/form-data`/二进制；P0 不设计文件上传 |

## 5. 幂等/并发

- `Idempotency-Key` 请求头：提交、发布、撤回、重新发布、更正、导入必须；
- 同键同请求体 → 返回首次结果；同键不同体 → 400/409 `IDEMPOTENCY_REPLAY`；
- 幂等记录至少保留 24h（实现阶段定），不能只存内存；
- 乐观锁：`version` 不匹配 → 409 `VERSION_CONFLICT`；
- 重复提交/审核/发布：先状态校验，再幂等键/唯一键；不能靠前端防重；
- 数据库唯一键是最后防线；冲突返回 409，不静默覆盖；
- 时间区间并发用行锁/事务，不能只靠 UNIQUE。

## 6. 认证与数据范围

- 所有 `/business/**` 需 JWT；除认证接口；
- 功能权限：`@PreAuthorize("@ss.hasPermi('business:...')")`；
- 数据范围：Service 重新读取当前用户/绑定/任职/发布状态，不信任客户端 `studentId/classId`；
- 系统管理员：若依 `ALL_PERMISSION` 可能绕过 `@PreAuthorize`，Service 必须显式拒绝成绩明细/导出；
- 前端菜单/按钮仅交互层；
- `@DataScope` 只用于若依部门范围，不替代本班/本人；
- `403` 与 `404` 不泄露他人资源是否存在：对越权对象优先返回 403 或统一 404，具体见安全测试。

## 7. URL/方法/查询

- 前缀 `/business/**`；资源名词复数；动作用子资源或动作段；
- `GET` 只读、`POST` 创建/动作、`PUT` 全量更新/状态、`DELETE` 撤销/解除（不物理删历史）；
- 路径参数放 ID；查询条件放 query；复杂事务放 body；
- 不以 `/dev-api` 作为后端路径；它只是 Vite 代理；
- 查询参数必须白名单；不允许客户端传 SQL/排序原文。

## 8. 兼容性结论

- 新业务 API 复用 `AjaxResult`/`TableDataInfo`，不改变若依前端拦截器主流程；
- 新增 `data.errorCode` 为**拟新增约定**，当前若依后端尚未实现；
- 新业务 Springdoc 文档需在实现后重新生成；当前 OpenAPI 为设计草稿；
- 现有接口运行时验证未完成（8080 未启动）。
