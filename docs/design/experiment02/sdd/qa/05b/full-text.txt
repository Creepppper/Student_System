1. 导言

1.1 编写目的
  本文描述高中学生信息与成绩管理系统的概要设计，说明系统边界、

总体架构、界面组织、数据模型、模块职责和主要接口，为后续详细设计、

编码和测试提供依据。预期读者为课程教师、评审人员和小组成员。


1.2 项目背景
  实验一已完成需求规格说明书 v1.1-review，形成四类业务角色、35 项

P0、11 项 P1、17 个业务数据对象及 ENT-08 班主任任职关联实体。实验

二以真实 RuoYi-Vue 源码为底座，完成源码分析、架构设计、数据库概

要设计和 API 契约设计。


1.3 系统目标
  在若依已有的登录、RBAC、菜单、部门、字典、日志、代码生成能

力之上，建立学生管理业务域：组织学年、学生档案、班主任任职、考试

配置、成绩任务、录入、审核、发布、学生本人查询、统计与业务审计。

系统保持前后端分离，成绩以数据库为真值，发布版本不可变，关键操作

可审计。


1.4 设计范围

计划学生业务   19 张 P0 表、3 张 P1 表、68 个 P0 API、11 个 P1 API

2. 系统分析

2.1 系统定位
  系统面向高中教务场景，支持学年/学期/年级/班级、学生档案、班主

任任职、考试与科目配置、成绩录入、教务审核发布、学生本人查询、统

计和业务审计。系统不是通用教务平台，也不包含任课教师/任教关系。


2.2 四类角色

角色               主要职责                 数据范围

系统管理员            账号、绑定、系统参数、脱 系统范围；**无成绩明细**
                 敏审计
                                      `SCOPE_ALL`
教务管理员            组织、考试、审核、发布、
                 撤回、更正、全校统计
                                      `SCOPE_CLASS`
班主任              当前有效任职班级的全科成
                 绩录入/提交/本班统计
                                      `SCOPE_SELF`
学生               本人已发布成绩查询、P1
                 复核申请




2.3 需求基线
• P0：35 项；P1：11 项；DR：17 个 + ENT-08；
• 成绩 0.5 分步长、一位小数；

• 未录入/缺考/真实零分三态分离；

• 班主任提交、教务审核、教务发布三权分离；

• 发布版本不可变，撤回保留历史，更正生成新版本。

  本版不重复实验一全部需求分析，只保留设计所需约束。

2.4 主要业务流程
教务维护组织/学生/班主任/科目
-> 教务创建考试、范围、科目/满分/线

-> 生成考试×班级×科目成绩任务（第一责任人快照）

-> 班主任录入本班全科、校验、提交

-> 教务审核通过/退回

-> 教务按考试×班级发布，生成不可变版本

-> 学生查看本人当前已发布成绩

-> 撤回/重发/受控更正，保留版本和审计

2.6 内容边界与一致性约束
   本版坚持以下边界，避免把规划写成实现：
• 若依 31 张现有表只读分析；19 张 P0/3 张 P1 是设计草稿，未创建；

• 68 P0/11 P1 API 是契约设计，未实现；

• 系统管理员不能因 ALL_PERMISSION 获得成绩明细；Service 显式拒绝；

• 班主任只操作当前有效任职班级；学生只读本人当前 PUB_PUBLISHED；

• 三态、0.5 分、审核/发布分离、撤回保留历史、更正生成新版本；

• 不恢复任课教师角色/任教关系；sys_user 不是学生，sys_dept 不是班级；

• P1 复核/导入导出/趋势/对比不进入 P0 退出条件；

• 未执行的 DDL、接口、测试均明确标注“未执行/未实现”。

4.3 分层与调用
Vue3 页面 -> src/api -> Axios(/dev-api 开发代理)
-> Spring Security/JWT -> Controller

-> Service（事务/状态/范围） -> Mapper/XML -> MariaDB
-> AjaxResult / TableDataInfo

• Controller 薄；Service 负责事务、状态机、权限范围、审计；

• Mapper 不承载业务状态；

• 前端菜单/按钮不是安全边界；

• /dev-api 只是 Vite 代理，不是后端路由。

6.1.1 核心模块功能说明
   （1）认证与账号—档案绑定。 复用若依登录、验证码、

JWT、/getInfo、/getRouters；学生/班主任业务身份通过

stu_account_binding 关联，一个档案最多一个有效账号，一个账号最多一

个有效绑定。系统管理员可管理账号/绑定，但服务层必须阻断成绩明细；

学生身份只从当前会话绑定解析，不接受客户端传入的 studentId。对应

FR-AUTH-003/004、STU-003；A/B 类能力。
   （2）学年、学期、年级、班级。 教务维护学年/学期/年级/班级；同一学年班级

名称/编码唯一，当前学年最多一个；班级不是 sys_dept。班级有学生/任务/发布后不

能物理删除，只能停用。对应 FR-ORG-001～004；C 类计划新增。

   （3）学生档案与归属。 教务维护学号、姓名、性别、学籍状态；学号全校唯一，

内部主键 id INT 与学号分离；转班通过 stu_student_class 关闭旧归属并新增，保留历

史。学生账号通过绑定表开通/撤销，不把账号字段塞入学生表。对应 FR-STU-001～

004；C 类。

   （4）班主任任职与科目。 班主任档案/任职历史独立于账号；一名班主任可负责

多个班，同一班级同一时刻最多一个当前任职；任务创建时保存第一责任人快照，换

班不覆盖历史。科目独立维护，不表示任教关系。对应 FR-ORG-005、FR-

TCH-001/002；C 类。

   （5）考试配置与成绩任务生成。 教务创建考试、考试班级范围、考试科目/满分

/及格线/优秀线；EXAM_DRAFT/OPEN/CLOSED/ARCHIVED 独立于任务/发布状态。

任务按考试×班级×科目唯一生成，保存花名册/满分线/第一责任人快照；重复生成幂等，

不重复插入。对应 FR-EXAM-001～004、FR-SCORE-001；C 类。

   （6）成绩录入、校验、提交。 班主任只录当前有效任职班级全科；分数

DECIMAL(6,1)、0.5 步长；三态 NORMAL/ABSENT/NOT_ENTERED；提交前无未录

6.4.2 API-SCORE-005 提交成绩任务
• 方法与路径： POST /business/score-tasks/{id}/submit
• 角色/权限： 班主任；business:score:submit；SCOPE_CLASS

• 请求体： VersionRequest：version required、idempotencyKey

• 成功： data=ScoreTask（状态 TASK_SUBMITTED）

• 关键校验： 任务 DRAFT/RETURNED、考试 OPEN、无 NOT_ENTERED、所有记

• 错误： 409 STATE_CONFLICT（未录入/已提交）、VERSION_CONFLICT；403。

• 表/事务： task/score/audit；单事务锁定+审计；幂等键必须。

6.4.3 API-SCORE-007 教务审核/退回
• 方法与路径： POST /business/score-tasks/{id}/review
• 角色/权限： 教务；business:score:review；SCOPE_ALL

• 请求体： ReviewRequest：action(APPROVE/RETURN)、reason(≤500)、version、
idempotencyKey

• 成功： data=ScoreTask；通过 TASK_APPROVED，退回 TASK_RETURNED

• 关键校验： TASK_SUBMITTED；审核人 ≠ 提交人；退回原因必填；version 匹配。

• 错误： 403 自审/越权；409 状态/版本；400 原因为空。

• 表/事务： task/audit；审核/退回+审计同事务。


6.4.4 API-PUB-002 发布班级成绩
• 方法与路径： POST /business/publications
• 角色/权限： 教务；business:publish:create；SCOPE_ALL

• 请求体： PublishRequest：examId、classId、version、idempotencyKey

• 成功： data=Publication，状态 PUB_PUBLISHED，版本+1

• 关键校验： 全部适用任务 TASK_APPROVED；无 SCORE_NOT_ENTERED；至少

一科；考试/班级一致；version/幂等。

• 错误： 409 STATE_CONFLICT/DUPLICATE_SUBMIT/VERSION_CONFLICT；

403。

• 表/事务： stu_publication、stu_publication_version、stu_publication_version_detail、

stu_audit_log；单事务生成不可变版本/明细/审计，任一步失败回滚。
