# 04 时序图与权限检查

> 图：FIG-08 P1 成绩复核时序图（跨人员异步）  
> 用例：UC-REVIEW-001（P1）；不进入 P0 退出条件  
> 结论：**学生申请本人已发布成绩；班主任受理/核查本班；教务最终确认/更正；三类结果明确；成绩记录/版本可追踪；无任课教师。**

## 1. 参与者

| 参与者 | 类型 | 职责 |
| --- | --- | --- |
| 学生 | Actor | 提交本人复核申请、查看结论/更正结果 |
| 业务系统 | 分析对象/参与者 | 资格/时限/重复校验、锁定成绩记录/版本、待办流转、版本与审计 |
| 班主任 | Actor | 本班受理并核查，提交核查意见；不最终确认 |
| 教务管理员 | Actor | 最终确认/驳回/受控更正；不替代班主任核查 |

`业务系统` 是分析对象，不新增业务 Actor；数据库/缓存/框架组件不是参与者。

## 2. 消息与权限

| 消息 | 发送→接收 | 权限/规则 |
| --- | --- | --- |
| 提交复核申请（考试/科目/理由/联系方式） | 学生→系统 | 仅本人；仅本人已发布成绩；同一学生+考试+科目最多 1 个活跃申请 |
| 校验本人已发布、时限、重复；锁定成绩记录 ID/版本 | 系统自处理 | 资格不符/超时/重复拒绝；不改变 P0 成绩 |
| 生成班主任待受理待办（异步） | 系统→班主任 | 只到该班当前班主任；跨人员异步，不是长同步请求 |
| 受理并提交核查意见 | 班主任→系统 | 仅本班；意见为无需修改/建议更正/建议驳回；不直接改分 |
| 转教务最终确认（异步） | 系统→教务 | 三类结果分别转待办 |
| 确认驳回 | 教务→系统 | 填写理由；学生可见结论 |
| 确认原成绩 | 教务→系统 | 无需更正；不改成绩 |
| 执行受控更正（原因/前后值/版本+1） | 教务→系统 | 仅教务；生成新版本，保留旧版本；重算总分/排名；写审计 |
| 复核结论/更正后成绩 | 系统→学生 | 仅申请人本人 |
| 查看结论 | 学生→系统 | 只读本人 |

## 3. 三类结果

| 结果 | 系统动作 | 成绩变化 | 学生可见 |
| --- | --- | --- | --- |
| 驳回 `REV_REJECTED` | 转教务确认驳回，写理由 | 不变 | 驳回结论/理由 |
| 无需更正 `REV_NO_CHANGE` | 教务确认原成绩 | 不变 | 无需更正结论 |
| 需要更正 `REV_CORRECTED` | 教务执行受控更正，生成新版本，写审计 | 变更并重算 | 更正后成绩/结论 |

> `alt` 三个分支均存在；不是把“无需更正”和“更正”混成一个结果。

## 4. 权限与 P0/P1 检查

| 检查 | 结果 |
| --- | --- |
| 学生只申请本人已发布成绩 | 通过；系统锁定本人成绩记录/版本 |
| 班主任只受理本班 | 通过；待办只生成给本班当前班主任 |
| 教务最终确认/更正 | 通过；唯一最终确认者 |
| 任课教师核查 | 不存在 |
| 班主任直接改分 | 禁止；只提交核查意见，更正由教务执行 |
| 发布后更正需原因/版本/审计 | 通过；生成新版本，保留历史 |
| 跨人员异步 | 通过；`->>` 异步待办，不是一次长同步请求 |
| P1 进入 P0 退出条件 | 否；P1 独立 |
| 数据库/技术组件 Actor | 无 |

## 5. 限制

- 图未展开通知/消息重试等非业务技术细节；
- `REV_*` 状态仍以基线字典为准，本阶段未新增状态；
- 复核时限 `D-019` 仍为课程模拟假设。
