# 04 时序图与权限检查

> 图：FIG-08 P1 成绩复核时序图  
> 用例：UC-REVIEW-001（P1）；不进入 P0 退出条件  
> 结论：**学生申请—系统校验—班主任受理/核查—教务最终确认/更正—学生查看；无任课教师，权限边界正确。**

## 1. 参与者

| 参与者 | 类型 | 职责 |
| --- | --- | --- |
| 学生 | Actor | 提交申请、查看结论/更正结果 |
| 业务系统 | 分析对象/参与者 | 资格/时限/重复校验、锁定成绩版本、流转、审计 |
| 班主任 | Actor | 本班受理并核查，给出核查意见；不最终确认 |
| 教务管理员 | Actor | 最终确认/驳回/受控更正；不替代班主任核查 |

`业务系统` 是分析对象，不是新增业务 Actor；不画数据库/缓存/框架组件为参与者。

## 2. 消息与权限

| 消息 | 发送→接收 | 权限/规则 |
| --- | --- | --- |
| 提交复核申请（考试/科目/理由/联系方式） | 学生→系统 | 仅本人；仅已发布成绩；同一学生+考试+科目最多 1 个活跃申请 |
| 校验资格/时限/重复；锁定成绩版本 | 系统自处理 | 资格不符/超时/重复→拒绝；不改变 P0 成绩 |
| 生成本班待受理任务 | 系统→班主任 | 只到该班当前班主任 |
| 受理并提交核查意见 | 班主任→系统 | 仅本班；不直接改分；核查意见必填 |
| 转教务最终确认 | 系统→教务 | 核查后转交；教务可确认/驳回 |
| 执行受控更正 | 教务→系统 | 仅教务；原因/前后值/版本+1；重算总分/排名；写审计 |
| 确认结论 | 教务→系统 | 最终确认；无更正时保留原成绩 |
| 复核结论/更正后成绩 | 系统→学生 | 仅申请人本人 |
| 查看结论 | 学生→系统 | 只读本人；P1 不改变 P0 可见性规则 |

## 3. alt/opt 分支

- `alt 资格/时限不符`：系统拒绝并说明原因；不生成班主任任务。
- `alt 资格通过`：进入受理。
- `alt 班主任核查后建议驳回`：转教务最终确认，教务确认驳回；学生看到理由。
- `else 核查通过/需更正`：转教务；`opt 需要更正` 时教务执行受控更正、版本+1、审计；然后确认结论。
- 学生最后查看结论/更正结果。

## 4. 权限与 P0/P1 检查

| 检查 | 结果 |
| --- | --- |
| 学生只申请本人 | 通过；系统锁定本人成绩 |
| 班主任只受理本班 | 通过；消息“本班待受理任务” |
| 教务最终确认/更正 | 通过；唯一最终确认者 |
| 任课教师核查 | 不存在 |
| 班主任直接改分 | 禁止；只提交核查意见，更正由教务执行 |
| 发布后更正需原因/版本/审计 | 通过；`opt` 中说明 |
| P0 被 P1 阻塞 | 否；P1 独立，未进入 P0 退出条件 |
| 审计 | 通过；更正/结论写业务审计 |
| 数据库/技术组件 Actor | 无 |

## 5. 限制

- 图未展开通知/消息重试等非业务技术细节；
- `REV_*` 状态在本图用“受理/核查/驳回/更正”表达，完整状态字典不在本阶段新增；
- 复核时限 `D-019` 仍为课程模拟假设。
