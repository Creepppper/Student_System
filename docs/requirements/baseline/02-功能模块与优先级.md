## 0. 口径声明

1. **当前所有业务模块均未实现。** 表中“实现状态”描述的是仓库现状，不是目标承诺。
2. P0/P1 是**交付优先级**，不是“是否写入需求文档”。P1 功能仍属于系统需求范围，SRS 和实验一原型可以描述它们，但不得在实现验收前标记为已具备。
3. 同一功能只能出现在一个优先级。模块级归属见第 2 节，功能级归属见第 3～5 节。
4. 功能 ID 采用 `FR-模块-序号`，一经进入基线不复用；删除时标“已废弃”，不重编号。

### 0.3 确认状态

- **已确认**：P0/P1/P2 的分期框架、五类角色范围、明确排除项（来自用户本阶段输入）。
- **建议**：具体模块拆分、功能 ID、每个功能的优先级归属、模块依赖与交付顺序。
- **待定**：具体功能是否调整、P1 是否在首期实现，以及受 `05` 高影响决策影响的实现范围。

## 3. P0 模块与功能

### 3.1 `MOD-AUTH` 身份认证与权限（P0）

**目标**：复用若依的认证与 RBAC，在其上建立五类业务角色和四类数据范围；不重写登录、JWT、菜单和按钮权限。

| 功能 ID | 功能 | 说明 | 主要角色 |
| --- | --- | --- | --- |
| `FR-AUTH-001` | 登录、登出、验证码 | 复用若依；登录失败提示不泄露账号是否存在 | 全部 |
| `FR-AUTH-002` | 用户、角色、菜单、按钮权限配置 | 复用若依；业务权限字符串使用 `business:*` 命名空间 | 系统管理员 |
| `FR-AUTH-003` | 业务角色分配与账号绑定 | 学生/教师档案与登录账号 1:1 关联；账号可后开通 | 系统管理员、教务管理员 |
| `FR-AUTH-004` | 业务数据范围过滤 | 学生本人、教师任教范围、班主任本班、教务全校 | 全部 |
| `FR-AUTH-005` | 账号启停与密码重置 | 复用若依；停用账号不能登录，但业务历史保留 | 系统管理员 |

**验收重点**：不能用前端隐藏代替后端校验；按 ID 直接访问他人数据必须被拒绝；内置 `admin` 不作为业务验收账号。

### 3.2 `MOD-ORG` 学年、学期、年级、班级（P0）

| 功能 ID | 功能 | 说明 | 主要角色 |
| --- | --- | --- | --- |
| `FR-ORG-001` | 学年管理 | 学年编码如 `2026-2027`；标记当前学年；保留历史 | 教务管理员 |
| `FR-ORG-002` | 学期管理 | 每学年两个学期；考试和任教关系挂学期 | 教务管理员 |
| `FR-ORG-003` | 年级管理 | 高一、高二、高三的层次与排序 | 教务管理员 |
| `FR-ORG-004` | 班级管理 | 班级属于学年+年级；班号/名称唯一；状态可归档 | 教务管理员 |
| `FR-ORG-005` | 班主任指派与变更 | 首期每班一名班主任；变更留痕 | 教务管理员 |

**验收重点**：班级不能跨学年混用；有学生或成绩的班级不能物理删除；班主任变更不改变历史成绩归属。

### 3.3 `MOD-STU` 学生基础信息（P0）

| 功能 ID | 功能 | 说明 | 主要角色 |
| --- | --- | --- | --- |
| `FR-STU-001` | 学生档案维护 | 学号、姓名、性别（可选）、入学年份、状态；敏感字段最小化 | 教务管理员 |
| `FR-STU-002` | 学生班级归属与变更 | 按学年记录归属；转班保留历史；不覆盖旧记录 | 教务管理员 |
| `FR-STU-003` | 学生账号开通与关联 | 档案与账号分离；可先有档案后开通账号 | 系统管理员、教务管理员 |
| `FR-STU-004` | 学生状态管理 | 在读、休学、转出、毕业；历史成绩不删除 | 教务管理员 |

**验收重点**：学号全校唯一；学生只能看本人；转班后历史考试仍归属原考试班级；毕业/转出学生不能被加入新考试范围。

### 3.4 `MOD-TCH` 教师、科目、任教关系（P0）

| 功能 ID | 功能 | 说明 | 主要角色 |
| --- | --- | --- | --- |
| `FR-TCH-001` | 教师档案维护 | 工号、姓名、状态；工号唯一；账号关联在账号侧完成 | 教务管理员 |
| `FR-TCH-002` | 科目维护 | 科目编码、名称、排序、状态；不写死六科 | 教务管理员 |
| `FR-TCH-003` | 任教关系维护 | 学年+学期+教师+班级+科目；唯一有效关系 | 教务管理员 |

**验收重点**：任教关系是成绩录入授权的唯一依据；班主任身份不自动获得全科录入权；关系变更要留痕。

### 3.5 `MOD-EXAM` 考试管理（P0）

| 功能 ID | 功能 | 说明 | 主要角色 |
| --- | --- | --- | --- |
| `FR-EXAM-001` | 考试创建与编辑 | 名称、类型（字典）、学年/学期、日期范围、说明 | 教务管理员 |
| `FR-EXAM-002` | 考试范围配置 | 参与班级；按班级配置适用科目；不适用科目显式排除 | 教务管理员 |
| `FR-EXAM-003` | 考试科目与分值配置 | 每科满分、及格线、优秀线；满分以考试科目为准 | 教务管理员 |
| `FR-EXAM-004` | 考试状态管理 | 草稿、已开放、已结束、已归档；控制录入窗口 | 教务管理员 |

**验收重点**：范围变更不能影响已提交/已发布数据；满分、及格线、优秀线必须可验证；考试结束不等于成绩自动发布。

### 3.6 `MOD-SCORE` 成绩录入与提交（P0）

| 功能 ID | 功能 | 说明 | 主要角色 |
| --- | --- | --- | --- |
| `FR-SCORE-001` | 成绩录入任务生成 | 按考试×班级×科目生成任务；记录责任教师和花名册快照 | 教务管理员 |
| `FR-SCORE-002` | 成绩录入与暂存 | 逐生录入；支持保存草稿；显示录入进度 | 任课教师 |
| `FR-SCORE-003` | 成绩校验 | 数值范围、精度、缺考/未录入、重复/冲突校验 | 任课教师、系统 |
| `FR-SCORE-004` | 成绩提交与退回后重提 | 提交后锁定；退回后可修改并重提（退回动作由教务审核功能处理） | 任课教师 |
| `FR-SCORE-005` | 缺考/未录入状态维护 | 缺考必须显式标记；未录入不能提交；零分是正常成绩 | 任课教师 |

**验收重点**：缺考、未录入、零分三者不能混；提交是原子操作；并发保存不能静默覆盖；任务只能由授权教师处理。

### 3.7 `MOD-PUB` 成绩审核与发布（P0）

| 功能 ID | 功能 | 说明 | 主要角色 |
| --- | --- | --- | --- |
| `FR-PUB-001` | 教务审核 | 逐任务“通过/退回”；退回必须填原因 | 教务管理员 |
| `FR-PUB-002` | 班级成绩发布 | 按考试×班级发布；要求该班所有适用科目任务已通过 | 教务管理员 |
| `FR-PUB-003` | 撤回发布 | 发布后发现严重问题可撤回；必须填原因；学生立即不可见 | 教务管理员 |
| `FR-PUB-004` | 发布后更正与版本 | 教务专用更正；记录前后值、原因、版本；重算总分/排名 | 教务管理员 |

**验收重点**：未审核不能发布；发布条件缺一科都不能发布；撤回不删除数据；更正不能由任课教师直接做。

### 3.8 `MOD-QUERY` 学生成绩查询（P0）

| 功能 ID | 功能 | 说明 | 主要角色 |
| --- | --- | --- | --- |
| `FR-QUERY-001` | 学生查询本人已发布成绩 | 按学年/学期/考试类型筛选；只返回本人已发布数据 | 学生 |
| `FR-QUERY-002` | 成绩明细、总分与班级排名展示 | 展示各科分数/缺考状态、总分、班级排名；不完整时说明原因 | 学生 |

**验收重点**：未发布/已撤回不可见；不能通过改 URL/ID 查他人；缺考显示“缺考”而不是 0；总分不完整时不排名。

### 3.9 `MOD-STAT` 基础成绩统计（P0）

| 功能 ID | 功能 | 说明 | 主要角色 |
| --- | --- | --- | --- |
| `FR-STAT-001` | 单场考试班级学科统计 | 参考人数、缺考数、未录入数、平均/最高/最低、及格率、优秀率、分数段 | 教务管理员、任课教师、班主任 |
| `FR-STAT-002` | 班级学生总分与排名汇总 | 授权范围内学生的总分、班级排名和完整性标记；任课教师不查看跨科总分 | 教务管理员、班主任 |

**验收重点**：统计分母口径一致；缺考/未录入单列；不同满分不能直接混算；P0 不做跨考试趋势和多班对比。

### 3.10 `MOD-AUDIT` 重要成绩业务变更记录（P0）

| 功能 ID | 功能 | 说明 | 主要角色 |
| --- | --- | --- | --- |
| `FR-AUDIT-001` | 成绩业务变更记录 | 成绩值/状态变化、任务提交/退回/通过、范围与花名册变化 | 教务管理员、系统管理员、任课教师（本人）、班主任（本班相关） |
| `FR-AUDIT-002` | 发布与撤回记录 | 发布、撤回、更正版本、影响范围 | 教务管理员、系统管理员、班主任（本班相关，只读） |

**验收重点**：记录不可由业务界面修改/删除；能还原前后值、操作人、时间、原因；通用接口日志不能替代业务变更记录。

## 4. P1 模块与功能

### 4.1 `MOD-REVIEW` 成绩复核（P1）

| 功能 ID | 功能 | 说明 | 主要角色 |
| --- | --- | --- | --- |
| `FR-REVIEW-001` | 学生提交复核申请 | 仅本人已发布成绩；按考试+科目；填写理由；有时限 | 学生 |
| `FR-REVIEW-002` | 班主任受理/驳回 | 本班申请；驳回必须填原因；受理后进入处理中 | 班主任 |
| `FR-REVIEW-003` | 任课教师核查意见 | 仅授权班级×科目；提交“无需修改/建议更正”及依据 | 任课教师 |
| `FR-REVIEW-004` | 复核结论确认 | 教务最终确认复核结论；确认需更正时调用 P0 的发布后更正能力 | 教务管理员 |
| `FR-REVIEW-005` | 学生查看复核结果 | 查看状态、处理意见、更正后的成绩 | 学生 |

**边界**：复核是 P1，不阻塞 P0；P0 的教务更正不是复核，二者不能共用“复核”状态名。

### 4.2 `MOD-IMPORT` Excel 导入导出（P1）

| 功能 ID | 功能 | 说明 | 主要角色 |
| --- | --- | --- | --- |
| `FR-IMPORT-001` | 导入模板下载 | 按考试×班级×科目生成模板；含学号、姓名、分数/缺考标记 | 任课教师 |
| `FR-IMPORT-002` | 导入预检与错误反馈 | 全量预检；返回行号、学号、错误原因；不部分写入 | 任课教师 |
| `FR-IMPORT-003` | 事务导入 | 预检通过后一次性导入；只允许草稿/已退回任务 | 任课教师 |
| `FR-IMPORT-004` | 成绩导出 | 按权限导出；字段最小化；记录导出行为 | 教务管理员、班主任、任课教师 |

**边界**：P0 不提供 Excel 导入/导出；P1 不得覆盖已提交/已通过/已发布成绩。

### 4.3 `MOD-TREND` 成绩趋势可视化（P1）

| 功能 ID | 功能 | 说明 | 主要角色 |
| --- | --- | --- | --- |
| `FR-TREND-001` | 学生个人成绩趋势 | 本人跨考试的单科/总分趋势；只含已发布数据 | 学生 |
| `FR-TREND-002` | 班级/学科成绩趋势 | 授权班级/科目的平均分、及格率等趋势；同口径才可比较 | 教务管理员、班主任、任课教师 |

**边界**：P0 只做单场考试统计；趋势不是 P0 的验收条件。

### 4.4 `MOD-COMPARE` 复杂班级对比分析（P1）

| 功能 ID | 功能 | 说明 | 主要角色 |
| --- | --- | --- | --- |
| `FR-COMPARE-001` | 多班级对比分析 | 同一考试、同一科目、同一满分口径下的班级指标对比 | 教务管理员、班主任（授权班级） |

**边界**：不做跨考试、跨试卷、不同满分口径的排名；不做班级“好坏”评价。

## 6. 功能归属检查

| 检查项 | 结果 |
| --- | --- |
| P0 功能 ID 是否出现在 P1 | 否；P0 共 36 个功能 ID |
| P1 功能 ID 是否出现在 P0 | 否；P1 共 12 个功能 ID |
| 同一功能是否有两个 ID | 否；每个功能只有一个 `FR-*` |
| P2/排除项是否分配 `FR-*` | 否；不进入本期需求基线 |
| 模块级 P0/P1 是否重叠 | 否；`MOD-*` 只属于一个优先级 |

> 说明：`FR-REVIEW-004` 是复核结论确认，在需要更正时复用 `FR-PUB-004` 的更正能力，但触发场景和权限入口不同；`FR-PUB-004` 仍是唯一的更正实现，避免出现两套改分逻辑。这不算同一功能重复归属。

## 8. P0/P1 边界规则

1. **P0 不含**：Excel 导入/导出、跨考试趋势图、多班级对比、学生复核申请、家长门户、任何预测推荐。
2. **P1 不改变 P0 的实体和状态名**：复核、导入、趋势、对比只能复用 P0 的成绩、任务、发布和审计模型，不能另建一套成绩真值。
3. **P0 的“发布后更正”不是复核**：更正由教务主动发起；复核由学生申请触发。
4. **P0 的“基础统计”不是趋势**：只统计单场考试、单班级、单科目；跨考试、跨班级属于 P1。
5. **课程实验一原型可以包含 P1 页面**：原型和 SRS 要覆盖复核等 P1 需求，但实现优先级仍是 P1，文档中必须标注“已规划、未实现”。
