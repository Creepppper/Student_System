## 0. 口径声明

1. 本文是**状态名、业务规则和计算口径的唯一权威来源**。其他文档引用状态时必须使用本文的状态代码和中文名，不得另造同义词。
2. 本文描述目标系统应遵守的规则；**当前没有任何业务模块实现**。
3. **缺考不是 0 分，未录入不是缺考，真实 0 分是正常成绩。** 三者在数据、页面、统计和排名中必须区分。
4. 规则 ID 采用 `BR-模块-序号`，一经进入基线不复用；删除时标“已废弃”，不重编号。
5. 本文只写业务规则，不写数据库字段、接口 URL、框架注解或页面组件。

> 规则表的“级别”列：**已确认** = 用户/课程硬约束；**建议** = 推荐默认值，待基线批准；**待定** = 依赖 `05` 的 `D-*` 决策，批准前不视为最终基线。

## 1. 状态命名规则

1. 状态代码使用 `实体_状态` 的大写英文，如 `TASK_SUBMITTED`；中文名固定，如“已提交”。
2. 同一业务状态只能有一个代码和一个中文名；不同实体即使中文相近，也必须用实体前缀区分，如 `TASK_RETURNED`（任务已退回）与 `REV_REJECTED`（复核已驳回）。
3. “可发布”“待审核”等是**条件或说明**，不是状态；不得另造“可发布/审核中”之类的额外状态代码。
4. 状态只能通过本文定义的转换事件改变；不得由前端直接赋值或后台脚本静默改状态。
5. 状态机核心代码使用稳定常量/枚举；字典只用于界面显示，不得通过改字典改变状态含义。

## 2. 状态字典

### 2.1 考试状态（`EXAM_*`）

| 代码 | 中文名 | 定义 | 学生可见性 | 允许的主要操作 |
| --- | --- | --- | --- | --- |
| `EXAM_DRAFT` | 草稿 | 考试配置中，尚未生成成绩任务 | 不可见 | 教务编辑范围/科目/分值；删除（无任务时） |
| `EXAM_OPEN` | 已开放 | 已生成任务，处于成绩录入窗口 | 不可见 | 教师录入/提交；教务审核；范围变更受严格限制 |
| `EXAM_CLOSED` | 已结束 | 录入窗口关闭，不再接受新的提交/修改 | 不可见（除非已发布） | 教务审核、发布、撤回、更正；可重开 |
| `EXAM_ARCHIVED` | 已归档 | 只读历史考试 | 已发布成绩仍可查 | 查询、统计；不可重开、不可改分 |

> “已结束”只表示录入窗口关闭，**不等于成绩已发布**；发布状态由 `PUB_*` 单独表达。

### 2.2 成绩录入任务状态（`TASK_*`）

| 代码 | 中文名 | 定义 | 可编辑 | 说明 |
| --- | --- | --- | --- | --- |
| `TASK_DRAFT` | 草稿 | 任务已生成，教师尚未提交 | 责任教师可编辑 | 未录入的成绩记录为 `SCORE_NOT_ENTERED` |
| `TASK_SUBMITTED` | 已提交 | 教师已提交，等待教务审核 | 否 | 锁定；教师不能自行撤回 |
| `TASK_RETURNED` | 已退回 | 教务退回，教师可修改后重提 | 责任教师可编辑 | 退回原因必填 |
| `TASK_APPROVED` | 已通过 | 教务审核通过，可参与班级发布 | 否 | 发布前如需修改，教务可退回 |

> 不使用“待审核”“审核中”作为任务状态；“已提交”已经表达等待审核。

### 2.3 班级成绩发布状态（`PUB_*`）

| 代码 | 中文名 | 定义 | 学生可见性 | 说明 |
| --- | --- | --- | --- | --- |
| `PUB_UNPUBLISHED` | 未发布 | 该班该考试尚未发布 | 不可见 | “所有任务已通过”只是可发布条件，不是状态 |
| `PUB_PUBLISHED` | 已发布 | 该班该考试成绩对学生可见 | 可见 | 发布后有版本号；更正不改变此状态，但版本增加 |
| `PUB_WITHDRAWN` | 已撤回 | 发布后被教务撤回 | 不可见 | 撤回原因必填；数据保留，可重新发布 |

> 发布单元是“考试×班级”，不是单个科目，也不是整场考试的所有班级。

### 2.4 成绩记录状态（`SCORE_*`）

| 代码 | 中文名 | 定义 | 是否有数值 | 计入总分/排名 | 计入统计分母 | 学生显示 |
| --- | --- | --- | --- | --- | --- | --- |
| `SCORE_NORMAL` | 正常 | 学生实际参加考试并有有效分数 | 是，`0 ≤ 分数 ≤ 满分` | 是（满足完整性时） | 是 | 分数 |
| `SCORE_ABSENT` | 缺考 | 学生应考但未参加，已由教师显式标记 | 否，数值为空 | 否；总分标记不完整 | 否；单独计数 | “缺考” |
| `SCORE_NOT_ENTERED` | 未录入 | 教师尚未填写，也无缺考标记 | 否，数值为空 | 否 | 否；单独计数 | 不显示（且不能发布） |

> **真实 0 分是 `SCORE_NORMAL` + 数值 0**，正常参与总分、排名和统计。  
> P0 不包含免考、缓考、作弊等状态；如要加入，必须新增状态并重新评审，不能临时借用 `SCORE_ABSENT` 或 0 分。

### 2.5 学生状态（`STU_*`）

| 代码 | 中文名 | 说明 |
| --- | --- | --- |
| `STU_ACTIVE` | 在读 | 可加入新考试范围，可开通账号 |
| `STU_SUSPENDED` | 休学 | 不加入新考试范围；历史成绩保留 |
| `STU_TRANSFERRED` | 转出 | 已转出本校；历史成绩保留；账号可停用 |
| `STU_GRADUATED` | 毕业 | 已完成学业；历史成绩保留；不加入新考试 |

### 2.6 教师状态（`TCH_*`）

| 代码 | 中文名 | 说明 |
| --- | --- | --- |
| `TCH_ACTIVE` | 在职 | 可被分配任教关系、班主任 |
| `TCH_INACTIVE` | 停用 | 不再新增关系；历史任务和成绩保留 |

### 2.7 班级状态（`CLASS_*`）

| 代码 | 中文名 | 说明 |
| --- | --- | --- |
| `CLASS_ACTIVE` | 在读 | 当前学年可用 |
| `CLASS_ARCHIVED` | 已归档 | 历史班级，只读；不可再加入新学生/新考试 |

### 2.8 复核申请状态（`REV_*`，P1）

| 代码 | 中文名 | 定义 | 终态 |
| --- | --- | --- | --- |
| `REV_PENDING` | 待受理 | 学生已提交，班主任尚未处理 | 否 |
| `REV_PROCESSING` | 处理中 | 班主任已受理，正在核查或待教务确认 | 否 |
| `REV_NO_CHANGE` | 无需修改 | 核查后确认成绩无误 | 是 |
| `REV_CORRECTED` | 已更正 | 教务确认并完成成绩更正 | 是 |
| `REV_REJECTED` | 已驳回 | 班主任或教务驳回申请 | 是 |
| `REV_WITHDRAWN` | 已撤回 | 学生在受理前撤回 | 是 |

> 不使用“已受理”作为独立状态；“处理中”表示已受理并正在处理。  
> 不使用“已撤销”；统一用“已撤回”。  
> 复核的“已驳回”与任务的“已退回”是不同实体，不能混用。

### 2.9 禁止使用的近义词

| 禁止写法 | 应使用的写法 | 原因 |
| --- | --- | --- |
| 待审核 / 审核中 | `TASK_SUBMITTED` 已提交 | 避免多出一个未定义状态 |
| 已撤销 | `PUB_WITHDRAWN` / `REV_WITHDRAWN` 已撤回 | 统一用“撤回” |
| 缺考 = 0 分 | `SCORE_ABSENT` 缺考，无数值 | 缺考不能污染平均分和排名 |
| 未填 = 缺考 | `SCORE_NOT_ENTERED` 未录入 | 未录入是工作未完成，不是考试事实 |
| 0 分 = 缺考 | `SCORE_NORMAL` + 0 | 真实零分是有效成绩 |
| 成绩批次（不区分） | 成绩录入任务 / 班级成绩发布 | 两个不同实体，不能共用一个模糊词 |
| 班级排名 = 年级排名 | 班级排名 / 年级排名 | P0 只做班级排名 |
| 发布 = 审核通过 | `PUB_PUBLISHED` / `TASK_APPROVED` | 通过不等于发布 |

## 3. 状态转换

### 3.1 考试状态转换

| 事件 ID | 事件 | 从 | 到 | 执行角色 | 守卫条件 | 审计 |
| --- | --- | --- | --- | --- | --- | --- |
| `E-EXAM-OPEN` | 开放考试 | `EXAM_DRAFT` | `EXAM_OPEN` | 教务管理员 | 至少 1 个班级、至少 1 个考试科目；每个科目满分 > 0；及格/优秀线合法 | 记录范围、科目、操作人 |
| `E-EXAM-CLOSE` | 结束录入 | `EXAM_OPEN` | `EXAM_CLOSED` | 教务管理员 | 记录未提交/未通过任务数量；不强制全部完成 | 记录关闭时间、未完成任务数 |
| `E-EXAM-REOPEN` | 重开录入 | `EXAM_CLOSED` | `EXAM_OPEN` | 教务管理员 | 必须填原因 | 记录原因、影响范围 |
| `E-EXAM-ARCHIVE` | 归档 | `EXAM_CLOSED` | `EXAM_ARCHIVED` | 教务管理员 | 不存在 `TASK_DRAFT`、`TASK_SUBMITTED`、`TASK_RETURNED` | 记录归档时间 |
| `E-EXAM-DELETE` | 删除草稿 | `EXAM_DRAFT` | 已删除 | 教务管理员 | 无任务、无成绩 | 记录删除快照 |

> `EXAM_ARCHIVED` 为终态；已发布成绩仍对学生可见。归档不等于删除。

### 3.2 成绩录入任务状态转换

| 事件 ID | 事件 | 从 | 到 | 执行角色 | 守卫条件 | 审计 |
| --- | --- | --- | --- | --- | --- | --- |
| `E-TASK-SUBMIT` | 提交成绩 | `TASK_DRAFT` / `TASK_RETURNED` | `TASK_SUBMITTED` | 责任任课教师 | 考试为 `EXAM_OPEN`；任务内无 `SCORE_NOT_ENTERED`；全部数值合法；版本号匹配 | 记录提交人、时间、成绩快照/变更 |
| `E-TASK-APPROVE` | 审核通过 | `TASK_SUBMITTED` | `TASK_APPROVED` | 教务管理员 | 审核人不是该任务录入人；成绩合法 | 记录审核人、时间 |
| `E-TASK-RETURN` | 退回 | `TASK_SUBMITTED` / `TASK_APPROVED` | `TASK_RETURNED` | 教务管理员 | 必须填原因；若从 `TASK_APPROVED` 退回，班级发布不能是 `PUB_PUBLISHED` | 记录原因、退回范围 |
| `E-TASK-RESUBMIT` | 退回后重提 | `TASK_RETURNED` | `TASK_SUBMITTED` | 责任任课教师 | 同 `E-TASK-SUBMIT` | 记录重提人、时间、变更 |

> 教师不能自行把 `TASK_SUBMITTED` 撤回为草稿；如需修改，由教务退回。

### 3.3 班级成绩发布状态转换

| 事件 ID | 事件 | 从 | 到 | 执行角色 | 守卫条件 | 审计 |
| --- | --- | --- | --- | --- | --- | --- |
| `E-PUB-PUBLISH` | 发布 | `PUB_UNPUBLISHED` | `PUB_PUBLISHED` | 教务管理员 | 该班所有适用科目任务均为 `TASK_APPROVED`；无 `SCORE_NOT_ENTERED`；至少 1 个适用科目 | 记录发布人、时间、版本 1、范围 |
| `E-PUB-WITHDRAW` | 撤回发布 | `PUB_PUBLISHED` | `PUB_WITHDRAWN` | 教务管理员 | 必须填原因 | 记录原因、影响范围、版本 |
| `E-PUB-REPUBLISH` | 重新发布 | `PUB_WITHDRAWN` | `PUB_PUBLISHED` | 教务管理员 | 更正后所有适用任务仍为 `TASK_APPROVED`；版本号递增 | 记录新版本、原因 |
| `E-PUB-CORRECT` | 发布后更正 | `PUB_PUBLISHED` | `PUB_PUBLISHED`（版本 +1） | 教务管理员 | 必须填原因；记录前后值；重算总分/排名 | 记录更正明细、版本、操作人 |

> `E-PUB-CORRECT` 不是状态转换，而是已发布数据的一个受控版本事件；学生看到更新后的成绩，发布状态仍为已发布。  
> 如果是系统性错误（多学生/多科目/口径错误），应走“撤回 → 退回 → 更正 → 重审 → 重新发布”，而不是逐条静默更正。

### 3.4 复核状态转换（P1）

| 事件 ID | 事件 | 从 | 到 | 执行角色 | 守卫条件 | 审计 |
| --- | --- | --- | --- | --- | --- | --- |
| `E-REV-SUBMIT` | 提交复核 | — | `REV_PENDING` | 学生 | 本人已发布成绩；在时限内；同一考试+科目无活跃申请 | 记录申请理由、成绩版本 |
| `E-REV-ACCEPT` | 受理 | `REV_PENDING` | `REV_PROCESSING` | 班主任 | 申请属于本班；班主任不是申请人 | 记录受理人、时间 |
| `E-REV-REJECT-PENDING` | 班主任驳回 | `REV_PENDING` | `REV_REJECTED` | 班主任 | 必须填原因 | 记录原因 |
| `E-REV-WITHDRAW` | 学生撤回 | `REV_PENDING` | `REV_WITHDRAWN` | 学生 | 尚未受理 | 记录撤回时间 |
| `E-REV-NOCHANGE` | 确认无需修改 | `REV_PROCESSING` | `REV_NO_CHANGE` | 教务管理员 | 任课教师已提交核查意见；必须填结论说明 | 记录结论、依据 |
| `E-REV-CORRECT` | 确认更正 | `REV_PROCESSING` | `REV_CORRECTED` | 教务管理员 | 任课教师建议更正或教务认定有误；更正走 `FR-PUB-004` | 记录前后值、原因、版本 |
| `E-REV-REJECT-PROCESS` | 教务驳回 | `REV_PROCESSING` | `REV_REJECTED` | 教务管理员 | 必须填原因 | 记录原因 |

> 任课教师提交核查意见不改变复核状态，仍是 `REV_PROCESSING`；这样避免出现“待核查/已核查”等额外状态。

## 4. 组织与学年规则（`BR-ORG`）

| ID | 规则 | 级别 |
| --- | --- | --- |
| `BR-ORG-001` | 系统面向单所高中，不设学校/租户维度；所有业务数据属于同一学校 | 已确认 |
| `BR-ORG-002` | 学年编码采用 `YYYY-YYYY`，有起止日期；同一时间只能有一个“当前学年”标记，历史学年保留 | 建议 |
| `BR-ORG-003` | 每个学年包含第一学期和第二学期；考试、任教关系必须引用已存在的学年+学期 | 建议 |
| `BR-ORG-004` | 年级为高一、高二、高三的层次，具有稳定代码和排序；年级不是班级 | 建议 |
| `BR-ORG-005` | 班级必须属于一个学年和一个年级，班号/名称在学年内唯一；每班首期一名班主任 | 建议 |
| `BR-ORG-006` | 有学生归属或有成绩的班级不得物理删除，只能归档；归档后不可加入新学生/新考试 | 建议 |
| `BR-ORG-007` | 有班级、考试或成绩引用的学年/学期不得物理删除 | 建议 |
| `BR-ORG-008` | 学生班级归属按学年记录；升年级、转班产生新归属，不覆盖旧归属 | 建议 |
| `BR-ORG-009` | 班主任变更必须审计；变更不影响历史成绩归属，只影响后续复核受理和班级查看范围 | 建议 |
| `BR-ORG-010` | 班级归档后，历史成绩、统计和已发布查询仍可用，但不可新增考试范围 | 建议 |

## 5. 学生规则（`BR-STU`）

| ID | 规则 | 级别 |
| --- | --- | --- |
| `BR-STU-001` | 学号全校唯一且稳定；确需更正时由教务执行并审计，不允许物理删除后重建 | 建议 |
| `BR-STU-002` | P0 学生档案只收集学号、姓名、性别（可选）、入学年份、状态、班级归属、账号关联；不收集身份证号、家庭住址、家长电话等敏感字段 | 建议 |
| `BR-STU-003` | 学生状态转换：在读→休学/转出/毕业；休学→在读/转出；转出、毕业为终态（如恢复需新流程） | 建议 |
| `BR-STU-004` | 每名学生在同一学年最多一条有效班级归属；转班必须结束旧归属再建立新归属，不得时间重叠 | 建议 |
| `BR-STU-005` | 成绩任务生成后再变更学生归属，必须由教务在任务为 `TASK_DRAFT`/`TASK_RETURNED` 时处理并审计；已提交/已通过/已发布时必须先退回或撤回 | 建议 |
| `BR-STU-006` | 学生档案与登录账号分离；一个学生最多关联一个账号；停用账号不删除档案和历史成绩 | 建议 |
| `BR-STU-007` | 有成绩的学生不得物理删除；只能改状态/归档 | 建议 |
| `BR-STU-008` | 非在读学生不能加入新的考试范围；历史已发布成绩仍保留 | 建议 |
| `BR-STU-009` | 学生只能查看本人档案中的允许字段和本人成绩；不得查看他人档案 | 建议 |

## 6. 教师、科目与任教关系规则（`BR-TCH` / `BR-SUB`）

### 6.1 教师与任教关系

| ID | 规则 | 级别 |
| --- | --- | --- |
| `BR-TCH-001` | 教师工号全校唯一；教师状态为 `TCH_ACTIVE` 时才能新增任教关系或班主任指派 | 建议 |
| `BR-TCH-002` | 任教关系由“学年+学期+教师+班级+科目”唯一确定；一名教师可有多条，一名学生可受多名教师任教 | 建议 |
| `BR-TCH-003` | 任教关系是成绩录入授权的唯一业务依据；班主任身份不自动产生任教关系 | 建议 |
| `BR-TCH-004` | 每班每学年一名班主任；班主任是班级属性，不是“所有科目教师” | 建议 |
| `BR-TCH-005` | 任教关系变更必须审计；已生成任务的责任教师按任务快照保留，不因关系变更自动换人 | 建议 |
| `BR-TCH-006` | 有任务/成绩引用的教师不得物理删除，只能停用 | 建议 |

| `BR-EXAM-011` | 考试类型用字典配置，不写死“月考/期中/期末”三种 | 建议 |

| `BR-SCORE-012` | 任教关系变更不自动改变已生成任务的责任教师；需教务重新指派并审计 | 建议 |

| `BR-SCORE-016` | 录入界面必须显示科目满分、精度和状态选择；校验失败要定位到学生和字段 | 建议 |
| `BR-SCORE-017` | P0 只支持手工录入，不提供 Excel 导入；批量导入属于 P1 | 建议 |

| ID | 规则 | 级别 |

| `BR-PUB-004` | 发布单元是“考试×班级”；该班所有适用科目任务都必须 `TASK_APPROVED`，且无 `SCORE_NOT_ENTERED` | 建议 |
| `BR-PUB-005` | 发布必须记录发布人、时间、版本和范围；学生只在发布后可见 | 建议 |

| `BR-PUB-009` | 单点更正可在 `PUB_PUBLISHED` 下直接执行，但必须记录前后值、原因、操作人和新版本，并重算总分/排名 | 建议 |
| `BR-PUB-010` | 系统性错误必须“撤回 → 退回 → 更正 → 重审 → 重新发布”，禁止逐条静默改分 | 建议 |
| `BR-PUB-011` | 缺考允许发布（显示“缺考”），但总分不完整；未录入不允许发布 | 建议 |
| `BR-PUB-012` | 适用科目为 0 的班级不能发布 | 建议 |
| `BR-PUB-013` | 录入人不能审核自己的任务；如一人多角色，必须由其他教务审核；无法满足时记录为课程项目简化并禁止自审 | 建议 |
| `BR-PUB-014` | 更正不能由录入教师执行；即使该教师同时有教务角色，也必须遵守职责分离 | 建议 |

## 10. 查询与排名规则（`BR-QUERY` / `BR-CALC`）

### 10.1 计算规则

| ID | 规则 | 级别 |
| --- | --- | --- |
| `BR-CALC-001` | 学生某场考试的总分 = 该生在该考试所有**适用科目**的 `SCORE_NORMAL` 数值之和 | 建议 |
| `BR-CALC-002` | 只要任一适用科目为 `SCORE_ABSENT` 或 `SCORE_NOT_ENTERED`，总分标记为“不完整”，不产生数值总分，不参与排名 | 建议 |
| `BR-CALC-003` | 班级排名只在该考试、该班级、总分完整的学生中计算；按总分降序，采用竞争排名：`名次 = 1 + 总分严格高于该生的人数`（同分为 1,2,2,4） | 建议 |
| `BR-CALC-004` | P0 只计算班级排名，不计算年级排名；不做不同选科/不同试卷的跨班总排名 | 建议 |
| `BR-CALC-005` | 平均分 = `SCORE_NORMAL` 数值之和 ÷ `SCORE_NORMAL` 条数；`SCORE_ABSENT`、`SCORE_NOT_ENTERED` 不计入分母 | 建议 |
| `BR-CALC-006` | 及格率 = 达到及格线的 `SCORE_NORMAL` 条数 ÷ `SCORE_NORMAL` 条数；优秀率同理；分母为 0 时显示“无有效成绩”，不显示 0% | 建议 |
| `BR-CALC-007` | 最高/最低分只从 `SCORE_NORMAL` 中取；无有效成绩时显示“无有效成绩” | 建议 |
| `BR-CALC-008` | 统计结果四舍五入保留 2 位小数；计算过程不提前取整，避免累计误差 | 建议 |
| `BR-CALC-009` | 不同满分的科目/考试不能直接比较原始分；需要比较时使用“得分率 = 分数 ÷ 满分”，并明确标注 | 建议 |

### 10.2 学生查询

| ID | 规则 | 级别 |
| --- | --- | --- |
| `BR-QUERY-001` | 学生只能查询本人、且 `PUB_PUBLISHED` 的班级成绩；`PUB_WITHDRAWN` 不可见 | 建议 |
| `BR-QUERY-002` | 学生看到：各科分数或“缺考”、总分（完整时）、班级排名（完整时）、发布状态；未录入不显示 | 建议 |
| `BR-QUERY-003` | 总分不完整时显示“不完整（原因：缺考/未录入）”，不显示数值总分，不显示排名 | 建议 |
| `BR-QUERY-004` | 学生不显示他人分数、他人排名、班级平均分、年级排名；只显示本人班级排名 | 建议 |
| `BR-QUERY-005` | 支持按学年/学期/考试类型筛选；默认展示最近一次已发布考试 | 建议 |
| `BR-QUERY-006` | 已归档考试的历史已发布成绩仍可查询；撤回后不可见 | 建议 |
| `BR-QUERY-007` | 撤回后学生再访问，显示“成绩已撤回/暂不可用”，不能继续显示旧值 | 建议 |
| `BR-QUERY-008` | 学生只能查看本人档案的允许字段；不得通过查询接口获取他人信息 | 建议 |
| `BR-QUERY-009` | P0 不提供成绩导出/打印；导出属于 P1 | 建议 |

## 11. 统计规则（`BR-STAT`）

| ID | 规则 | 级别 |
| --- | --- | --- |
| `BR-STAT-001` | P0 统计范围：单场考试、单班级、单科目；指标包括有效人数、缺考数、未录入数、平均分、最高分、最低分、及格率、优秀率、分数段 | 建议 |

| `BR-STAT-003` | 及格/优秀判定使用该考试科目配置的百分比线，不写死 60/85 分 | 建议 |
| `BR-STAT-004` | 分数段按得分率划分：`[0,60%)`、`[60%,70%)`、`[70%,80%)`、`[80%,90%)`、`[90%,100%]`；只统计 `SCORE_NORMAL` | 建议 |
| `BR-STAT-005` | 班级总分/排名汇总只统计总分完整的学生；不完整学生单列并注明原因 | 建议 |
| `BR-STAT-006` | 任课教师只能看本人任教班级×科目的统计；班主任可看本班全科汇总（已提交/已通过/已发布）；教务看全校；学生不看班级统计，只看本人汇总（`FR-QUERY-002`） | 建议 |
| `BR-STAT-007` | P0 不做跨考试趋势、多班级对比、年级排名、预测分析 | 建议 |
| `BR-STAT-008` | 统计页面必须显示口径说明（分母、缺考处理、满分、及格线），避免误读 | 建议 |
| `BR-STAT-009` | 统计结果不作为成绩真值；以成绩记录和发布版本为准 | 建议 |
| `BR-STAT-010` | 不同满分/不同科目的统计不能直接合并；必须分科或归一化后展示 | 建议 |

| `BR-AUTH-003` | 任课教师数据范围由“学年+学期+班级+科目”任教关系决定；不能通过请求参数扩大 | 建议 |
| `BR-AUTH-004` | 班主任数据范围为本班；默认只读成绩，除非同时具备该班该科任教关系 | 建议 |
| `BR-AUTH-005` | 教务管理员数据范围为全校教务数据；发布/更正仍受状态机和职责分离约束 | 建议 |
| `BR-AUTH-006` | 系统管理员只管账号、角色、菜单、配置和系统日志；不默认查看成绩明细、不参与审批 | 建议 |
| `BR-AUTH-007` | 角色组合时功能权限取并集、数据范围取并集；但不得因此获得自审、自改或超范围数据 | 建议 |
| `BR-AUTH-008` | 任何按 ID 读取/修改的接口都必须校验该 ID 是否落在当前用户数据范围内，防止水平越权 | 建议 |
| `BR-AUTH-009` | 统计、导出、详情、批量接口与列表接口使用同一数据范围，不能“列表过滤、详情不过滤” | 建议 |
| `BR-AUTH-010` | 业务权限字符串使用 `business:*` 命名空间，不复用若依系统权限字符串 | 建议 |
| `BR-AUTH-011` | 内置超级管理员只用于初始化/应急，不用于业务验收；业务审批使用独立角色账号 | 建议 |
| `BR-AUTH-012` | 同一账号不得审批自己录入的任务，也不得确认自己申请的复核更正 | 建议 |
| `BR-AUTH-013` | 教师停用、班主任更换、学生转班/毕业后，编辑权限按当前关系收回；历史数据保留，查询权限按新关系授予 | 建议 |

## 16. 关键边界与异常

| 场景 | 规则 |
| --- | --- |
| 教师录入了 0 分 | 保存为 `SCORE_NORMAL` + 0；参与总分、排名、统计；页面显示 0 |
| 学生缺考 | 教师显式标记 `SCORE_ABSENT`；页面显示“缺考”；总分不完整、不排名；统计分母不含该生该科 |
| 教师漏填 | 保持 `SCORE_NOT_ENTERED`；不能提交、不能发布；学生不可见 |
| 一个学生缺考一科 | 该科显示缺考；总分不完整、不参与班级排名；其余科目正常统计 |
| 全班无有效成绩 | 统计显示“无有效成绩”；不出现除以 0 或 0% 冒充结果 |
| 两位学生总分相同 | 竞争排名：1,2,2,4；后续名次跳号 |
| 发布时某科未通过 | 阻止发布，提示未通过科目；不能“先发布再补” |
| 发布后单科错误 | 教务单点更正，记录前后值/原因/版本，重算排名；不撤回整班 |
| 发布后多科/系统性错误 | 撤回发布 → 退回相关任务 → 更正 → 重审 → 重新发布；版本递增 |
| 撤回后学生访问 | 显示“成绩已撤回/暂不可用”；不显示旧分数 |
| 教师提交后想改 | 不能自行撤回；联系教务退回 |
| 两位教师同时保存同一任务 | 乐观锁冲突；后保存者收到提示，不静默覆盖 |
| 任务生成后学生转班 | 仅教务在草稿/已退回阶段调整花名册并审计；已提交/发布需先退回/撤回 |
| 任教关系变更 | 已生成任务保留原责任教师；新教师需教务重新指派并审计 |
| 考试关闭后教师想补录 | 教务重开考试（填原因）后，教师才能继续；不能绕过状态 |
| 学生查看已归档考试 | 已发布成绩仍可查；未发布/已撤回不可见 |

## 18. 一致性检查

- [x] 每个业务状态有唯一代码和中文名，且给出转换事件；
- [x] 考试、任务、发布、成绩、复核状态相互独立，不用一个词表达多个实体；
- [x] 缺考、未录入、零分在数据、页面、统计、排名中区分；

- [x] 审计与业务变更同事务，且不能由界面修改；

- [x] 未把未实现功能写成已具备。
