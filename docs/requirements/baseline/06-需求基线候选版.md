## 1. 基线声明

### 1.1 本基线是什么

本基线定义 **高中学生信息与成绩管理系统** 在单所高中、首期范围内的：

- 系统定位与边界；
- 五类业务角色、功能权限和数据权限；
- P0/P1/P2/排除的功能模块与优先级；
- 成绩主链路的状态机、业务规则和计算口径；
- 影响建模与实现的关键决策及其当前状态；
- 后续 SRS、DFD、ER、UML、原型和测试的追溯入口。

### 1.2 本基线不是什么

- 不是正式 SRS，不展开完整用例规约、数据字典、界面细节和验收测试；
- 不是设计文档，不规定数据库表、接口 URL、类名或 Vue 组件；
- 不是实现承诺：**当前仓库只有若依基础能力，所有业务模块均未实现**；
- 不是“已经批准”的基线：带 `建议`/`待定` 的内容在用户拍板前不构成最终承诺。

### 1.3 当前实现现状

| 能力 | 现状 |
| --- | --- |
| 若依登录、JWT、验证码、RBAC、菜单、按钮权限、字典、操作日志 | 已有基础能力 |
| 五类业务角色、业务数据范围、账号与档案绑定 | 未实现 |
| 学年/学期/年级/班级、学生、教师、科目、任教关系 | 未实现 |
| 考试、成绩录入、审核发布、学生查询、统计、审计 | 未实现 |
| 复核、导入导出、趋势、班级对比 | 未实现（P1） |
| 家长门户、预测推荐、多校 SaaS | 不规划/排除 |

## 3. 系统定位

【已确认】单所高中，围绕学年、学期、年级、班级、学生、教师、科目、考试、成绩和成绩发布开展管理。

【已确认】不扩展为大学选课/学分/GPA、完整智慧校园 ERP、多校 SaaS、高考预测/志愿推荐。

【建议】一句话：

> 面向单所高中的教务、教师和学生，提供“基础资料 → 考试配置 → 成绩录入 → 审核发布 → 学生查询 → 变更留痕”的闭环，并在 P1 增加复核、导入导出和趋势分析。

### 4.3 主链路

```text
基础资料（学年/学期/年级/班级/学生/教师/科目/任教关系）
  → 考试配置（范围/科目/满分/及格线/优秀线）
  → 成绩任务生成（考试×班级×科目）
  → 任课教师录入/校验/提交
  → 教务逐任务审核（通过/退回）
  → 按考试×班级发布
  → 学生查询本人已发布成绩/总分/班级排名
  → 关键变更审计
```

P1 在此之上增加：复核、Excel 导入导出、趋势、班级对比。

## 5. 角色与权限摘要

| 角色 | 功能边界 | 数据范围 |
| --- | --- | --- |
| 系统管理员 | 账号、角色、菜单、配置、系统日志 | 系统管理数据；不看成绩明细、不审批 |
| 教务管理员 | 教务基础资料、考试、审核发布、更正、统计 | 全校教务数据 |
| 任课教师 | 授权班级×科目成绩录入/提交；P1 核查 | 任教关系覆盖的班级×科目×学期 |
| 班主任 | 本班学生与成绩汇总只读；P1 复核受理 | 本人担任班主任的班级 |
| 学生 | 本人已发布成绩查询；P1 复核申请 | 仅本人 |

【建议】功能权限和数据权限必须同时满足；前端隐藏不作为安全措施。完整矩阵见 [03](03-角色与权限边界.md)。

## 13. 变更控制

1. 批准前：可直接修改候选稿，但每次修改要更新版本号和变更说明。
2. 批准后：任何范围、角色、状态、规则、优先级变化必须提出变更请求（CR），记录：
   - 变更原因；

   - 批准人、日期、生效版本。

4. 未批准的“建议/待定”不得在 SRS 或代码中写成既定事实。
