## 1. 基线声明

### 1.1 本基线是什么

本文件是 **`BL-REQ-001 v1.0-provisional` 工作基线**，记录用户本次采用的课程项目需求决策。它定义 **高中学生信息与成绩管理系统** 在单所高中、首期范围内的：

- 系统定位与边界；
- 四类业务角色、功能权限和数据权限；
- P0/P1/P2/排除的功能模块与优先级；
- 成绩主链路的状态机、业务规则和计算口径；
- 影响建模与实现的关键决策及其当前状态；
- 后续 SRS、DFD、ER、UML、原型和测试的追溯入口。

### 1.2 本基线不是什么

- 不是正式 SRS，不展开完整用例规约、数据字典、界面细节和验收测试；
- 不是设计文档，不规定数据库表、接口 URL、类名或 Vue 组件；
- 不是实现承诺：**当前仓库只有若依基础能力，所有业务模块均未实现**；
- 不是小组/老师正式批准的基线：本版是“用户采用的课程项目工作基线，小组正式评审待确认”；
- `D-019` 的复核时限是课程模拟假设，不是真实学校制度。

### 1.3 当前实现现状

| 能力 | 现状 |
| --- | --- |
| 若依登录、JWT、验证码、RBAC、菜单、按钮权限、字典、操作日志 | 已有基础能力 |
| 四类业务角色、业务数据范围、账号与档案绑定 | 未实现 |
| 学年/学期/年级/班级、学生、班主任、科目、班主任任职 | 未实现 |
| 考试、成绩录入、审核发布、学生查询、统计、审计 | 未实现 |
| 复核、导入导出、趋势、班级对比 | 未实现（P1） |

## 3. 系统定位

【已采用】单所高中，围绕学年、学期、年级、班级、学生、班主任、科目、考试、成绩和成绩发布开展管理。

【已采用】不扩展为大学选课/学分/GPA、完整智慧校园 ERP、多校 SaaS、高考预测/志愿推荐。

【工作基线】一句话：

> 面向单所高中的教务、班主任和学生，提供“基础资料 → 考试配置 → 成绩录入 → 审核发布 → 学生查询 → 变更留痕”的闭环，并在 P1 增加复核、导入导出和趋势分析。

### 4.3 主链路

```text
基础资料（学年/学期/年级/班级/学生/班主任/科目/班主任任职）
  → 考试配置（范围/科目/满分/及格线/优秀线）
  → 成绩任务生成（考试×班级×科目）
  → 班主任录入/校验/提交
  → 教务逐任务审核（通过/退回）
  → 按考试×班级发布
  → 学生查询本人已发布成绩/总分/班级排名
  → 关键变更审计
```

P1 在此之上增加：复核、Excel 导入导出、趋势、班级对比。
