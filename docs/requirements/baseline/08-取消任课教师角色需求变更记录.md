# 08 取消任课教师角色需求变更记录

> 基线编号：`BL-REQ-001`  
> 变更前版本：`v1.1-provisional`  
> 变更后版本：`v1.2-provisional`  
> 状态：**用户采用的课程项目工作基线，小组正式评审待确认**  
> 日期：2026-10-28  
> 变更来源：用户 2026-10-28 正式决定  
> 性质：正式需求变更记录；不是老师评审、不是小组批准、不是代码变更

## 1. 变更原因

原 v1.1 方案同时保留“班主任”和“任课教师”两类教师端角色，并维护“教师×班级×科目”的任教关系。该方案会带来：

1. 权限矩阵需要同时处理班主任本班全科和任课教师本人科目，角色叠加与数据范围复杂；
2. 成绩任务需要维护班主任、任课教师、第一责任人、重叠编辑和双角色责任；
3. P1 复核需要额外增加任课教师核查环节；
4. 后续 Spring Boot 3 + Vue 3 若依项目的角色、菜单、数据权限、数据库关系和页面都更复杂。

用户决定取消任课教师角色，**教师端只保留班主任**，以简化权限、业务、数据库和页面设计。

## 2. 角色变更对照

| 项 | 变更前 v1.1 | 变更后 v1.2 |
| --- | --- | --- |
| 系统管理员 | `ROLE_SYS_ADMIN` | `ROLE_SYS_ADMIN`（不变） |
| 教务管理员 | `ROLE_ACADEMIC` | `ROLE_ACADEMIC`（不变） |

| 角色数量 | 5 | 4 |
| 数据范围 | SYSTEM/ALL/ASSIGNED/CLASS/SELF | SYSTEM/ALL/CLASS/SELF |

## 3. 原方案与新方案

### 3.1 原方案（v1.1）

- 班主任：本班全科成绩录入/修改；任课教师：按任教关系录入/修改本人科目。
- 成绩任务记录班主任第一责任人、该科任课教师；两者可重叠编辑。
- P1 复核：学生申请 → 班主任受理 → 任课教师核查 → 教务确认/更正。
- 教师档案与“教师×班级×科目”任教关系分开维护。

### 3.2 新方案（v1.2）

- 班主任：本班全科成绩录入/修改/提交；查看本班统计；P1 受理并核查。
- 任课教师：取消；不再维护任教关系。
- 成绩任务：考试×班级×科目，第一责任人为班主任；只有本班班主任可编辑。
- P1 复核：学生申请 → 班主任受理并核查 → 教务最终确认/更正 → 学生查看。
- 科目仍保留；班主任负责本班全部适用科目。

## 9. 对后续建模与实现的影响

### 9.1 ER
- 删除“任教关系”实体；班主任与班级的关系通过“班级.班主任/班主任任职”表达。
- 成绩任务只保留班主任第一责任人，不再有 subject_teacher。
- 班主任档案与账号 1:1；科目独立保留。

### 9.2 DFD
- 删除“按科目分配任课教师”数据流/加工。
- 成绩录入加工只接收班主任；复核加工去掉任课教师核查分支。
- 保留：班主任录入本班全科、教务审核发布、学生查询。

### 9.3 UML
- 总用例图 Actor 只保留四类；删除任课教师 Actor 和任教关系用例。
- 成绩录入活动图/复核时序图改为“班主任→教务”，无任课教师。
- 状态机不变（考试/任务/发布/复核状态名保持）。

### 9.4 原型

- 现行图表/原型规划见 [图表与原型规划-v1.2](../图表与原型规划-v1.2.md)。
- 不设计任课教师工作台/按科目分配任课教师页面。
- 保留班主任成绩录入、本班成绩查询/统计页面。
- 保留教务审核发布页面。
- P1 保留班主任受理查分申请页面。

### 9.5 实现
- 若依角色表只配置四类业务角色；不创建 `ROLE_TEACHER`。
- 不创建任教关系表/字段/数据权限。
- 班主任本班全科权限通过 `SCOPE_CLASS` 实现；教务 `SCOPE_ALL`；学生 `SCOPE_SELF`。
- 成绩任务并发仍使用版本号/乐观锁。
