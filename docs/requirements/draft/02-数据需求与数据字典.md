# 02 数据需求与数据字典

> 项目：高中学生信息与成绩管理系统  
> 基线：`BL-REQ-001 v1.2-provisional`  
> 文档版本：`v0.2-draft`  
> 状态：**第 2 阶段数据需求初稿，待用户/小组审核**  
> 日期：2026-10-28  
> 范围：17 个业务数据对象（含账号-档案关联）的概念、属性、约束、唯一性和关联规则  
> 说明：**本阶段不创建数据库表、不写 SQL、不声明物理外键**；本文是概念/逻辑数据需求，物理设计留到数据库设计阶段。

## 0. 说明

1. 本文使用业务术语，不绑定 MariaDB/MySQL 具体类型；物理字段、索引、字符集在主设计阶段确定。
2. 逻辑关联不等于物理外键；本文不宣称数据库已实现任何约束。
3. 状态代码以 [04-核心业务规则](../baseline/04-核心业务规则.md) 第 2 节为准，本文不另造状态。
4. 分数、满分、及格线、优秀线统一 0.5 分步长、一位小数；计算/比较使用定点十进制，禁止二进制浮点直接比较。
5. 学生档案与登录账号分离；账号/角色/菜单等若依已有实体不重复定义，只在关联处说明。
6. P1 复核申请单独定义，标记 `P1`；不并入 P0 数据真值。

## 2. 组织与人员数据

### DR-ORG-001 学年

- 概念：一个教学年度，如 `2026-2027`，为学期、班级、考试和班主任任职提供时间边界。
- 业务属性：

| 数据项 | 含义 | 格式/取值 | 约束 |
| --- | --- | --- | --- |
| `school_year_id` | 逻辑主键 | 整数/代理键 | 唯一、不可复用 |
| `year_code` | 学年编码 | `YYYY-YYYY` | 全校唯一；后一年 = 前一年 + 1 |
| `year_name` | 显示名称 | 文本 | 非空 |
| `start_date` | 开始日期 | 日期 | ≤ 结束日期 |
| `end_date` | 结束日期 | 日期 | ≥ 开始日期 |
| `is_current` | 是否当前学年 | 布尔 | 同一时间最多一个为真 |
| `status` | 生命周期 | 有效/归档 | 归档后不可新增班级/考试 |

- 业务唯一性：`year_code` 全校唯一；当前学年唯一。
- 关联规则：一个学年包含两个学期；班级、考试、班主任任职必须引用学年。
- 删除规则：被班级/考试引用时不得物理删除；只能归档。

### DR-ORG-002 学期

- 概念：学年内的第一/第二学期，是考试和班主任任职的时间维度。
- 业务属性：

| 数据项 | 含义 | 格式/取值 | 约束 |
| --- | --- | --- | --- |
| `term_id` | 逻辑主键 | 代理键 | 唯一 |
| `school_year_id` | 所属学年 | 引用学年 | 必须存在 |
| `term_no` | 学期序号 | 1/2 | 同一学年唯一 |
| `start_date` / `end_date` | 起止日期 | 日期 | 落在学年内；开始≤结束 |
| `status` | 状态 | 有效/归档 | 归档后不可被新考试引用 |

- 业务唯一性：同一学年 `term_no` 唯一。
- 关联规则：考试、班主任任职挂学年+学期；不跨学期混用。

### DR-ORG-003 年级

- 概念：高一、高二、高三的年级层次，具有稳定代码和排序。
- 业务属性：

| 数据项 | 含义 | 格式/取值 | 约束 |
| --- | --- | --- | --- |
| `grade_id` | 逻辑主键 | 代理键 | 唯一 |
| `grade_code` | 年级代码 | 文本 | 唯一 |
| `grade_name` | 年级名称 | 高一/高二/高三 | 唯一 |
| `sort_order` | 排序 | 整数 | 稳定 |
| `status` | 状态 | 有效/停用 | 被班级引用后不可删除 |

- 关联规则：班级属于一个学年+一个年级；年级不是班级。
- 删除规则：被班级引用时只能停用。

### DR-ORG-004 班级

- 概念：某学年某年级下的行政班，如“2026-2027 学年高一(1)班”。
- 业务属性：

| 数据项 | 含义 | 格式/取值 | 约束 |
| --- | --- | --- | --- |
| `class_id` | 逻辑主键 | 代理键 | 唯一 |
| `school_year_id` | 所属学年 | 引用学年 | 必须存在 |
| `grade_id` | 所属年级 | 引用年级 | 必须存在 |
| `class_code` | 班号/编码 | 文本 | 学年内唯一 |
| `class_name` | 班级名称 | 文本 | 学年内唯一；建议含年级/班号 |
| `homeroom_teacher_id` | 班主任 | 引用班主任 | 首期每班一名；在职；可变更留痕 |
| `status` | 状态 | `CLASS_ACTIVE`/`CLASS_ARCHIVED` | 归档后不可加入新学生/新考试 |

- 业务唯一性：同一学年 `class_code`、`class_name` 唯一；一个班级只属于一个学年+年级。
- 关联规则：学生归属、考试范围、成绩任务、班级发布都引用班级；班主任按本班获得全科录入/查看范围。
- 删除规则：有学生或成绩时不得物理删除，只能归档。

### DR-STU-001 学生

- 概念：业务档案中的学生，不等同于登录账号；保存教学管理所需最小信息。
- 业务属性：

| 数据项 | 含义 | 格式/取值 | 约束 |
| --- | --- | --- | --- |
| `student_id` | 逻辑主键 | 代理键 | 唯一 |
| `student_no` | 学号 | 文本 | 全校唯一、稳定；更正需审计 |
| `name` | 姓名 | 文本 | 非空 |
| `gender` | 性别 | 男/女/未填 | 可选 |
| `enrollment_year` | 入学年份 | 年份 | 合理范围 |
| `status` | 状态 | `STU_ACTIVE`/`STU_SUSPENDED`/`STU_TRANSFERRED`/`STU_GRADUATED` | 状态转换受规则约束 |
| `user_id` | 关联账号 | 引用若依用户 | 可空；最多 1:1 |

- 业务唯一性：`student_no` 全校唯一；一个学生最多一个账号。
- 隐私：P0 不收集身份证号、家庭住址、家长电话等；如后续需要，单独评审。
- 删除规则：有成绩不得物理删除；只能改状态/归档。

### DR-STU-002 学生班级归属

- 概念：学生在某学年的班级归属历史，支持转班、升学和毕业追溯。
- 业务属性：

| 数据项 | 含义 | 格式/取值 | 约束 |
| --- | --- | --- | --- |
| `membership_id` | 逻辑主键 | 代理键 | 唯一 |
| `student_id` | 学生 | 引用学生 | 必须存在 |
| `school_year_id` | 学年 | 引用学年 | 必须存在 |
| `class_id` | 班级 | 引用班级 | 属于该学年；未归档 |
| `start_date` / `end_date` | 生效起止 | 日期 | 不重叠；结束≥开始 |
| `status` | 状态 | 有效/已结束 | 同一学年最多一条有效 |

- 业务唯一性：同一学生同一学年最多一条有效归属。
- 关联规则：成绩任务花名册按任务快照；历史成绩保留考试时班级；转班先结束旧归属再建新归属。
- 删除规则：不物理删除历史归属；只结束。

## 3. 班主任与科目

### DR-TCH-001 班主任

- 概念：业务档案中的班主任（教学人员），不等同于登录账号；系统教学侧只保留班主任角色。
- 业务属性：

| 数据项 | 含义 | 格式/取值 | 约束 |
| --- | --- | --- | --- |
| `teacher_id` | 逻辑主键 | 代理键 | 唯一 |
| `teacher_no` | 工号 | 文本 | 全校唯一 |
| `name` | 姓名 | 文本 | 非空 |
| `status` | 状态 | `TCH_ACTIVE`/`TCH_INACTIVE` | 停用后不可被指派新班级 |
| `user_id` | 关联账号 | 引用若依用户 | 可空；最多 1:1 |

- 业务唯一性：`teacher_no` 全校唯一；一个班主任最多一个账号。
- 删除规则：有任务/成绩/班级任职时只能停用。

### DR-TCH-002 科目

- 概念：可配置的科目主数据，不写死六科。
- 业务属性：

| 数据项 | 含义 | 格式/取值 | 约束 |
| --- | --- | --- | --- |
| `subject_id` | 逻辑主键 | 代理键 | 唯一 |
| `subject_code` | 科目编码 | 文本 | 唯一 |
| `subject_name` | 科目名称 | 文本 | 唯一 |
| `sort_order` | 排序 | 整数 | 稳定 |
| `status` | 状态 | 有效/停用 | 被考试科目引用后不可删除 |

- 关联规则：科目不决定考试满分；满分以考试科目为准；停用不影响历史考试。
- 删除规则：被引用时只能停用。

## 4. 考试数据

### DR-EXAM-001 考试

- 概念：一次有名称、类型、学期、日期和状态的教学测验。
- 业务属性：

| 数据项 | 含义 | 格式/取值 | 约束 |
| --- | --- | --- | --- |
| `exam_id` | 逻辑主键 | 代理键 | 唯一 |
| `exam_name` | 考试名称 | 文本 | 同一学年+学期唯一 |
| `exam_type` | 类型 | 字典：月考/期中/期末/其他 | 不写死三种 |
| `school_year_id` / `term_id` | 学年/学期 | 引用 | 必须存在 |
| `start_date` / `end_date` | 考试日期 | 日期 | 合法；与学期不冲突 |
| `status` | 状态 | `EXAM_DRAFT`/`EXAM_OPEN`/`EXAM_CLOSED`/`EXAM_ARCHIVED` | 只按状态机转换 |
| `created_by` / `created_at` | 创建人/时间 | 引用用户/时间 | 审计 |

- 业务唯一性：同一学年+学期 `exam_name` 唯一。
- 关联规则：考试范围、考试科目、成绩任务、发布都引用考试。
- 删除规则：仅 `EXAM_DRAFT` 且无任务/成绩可删除；否则归档。

### DR-EXAM-002 考试班级范围

- 概念：某场考试参与哪些班级，以及每个班级的适用科目范围。
- 业务属性：

| 数据项 | 含义 | 格式/取值 | 约束 |
| --- | --- | --- | --- |
| `exam_scope_id` | 逻辑主键 | 代理键 | 唯一 |
| `exam_id` | 考试 | 引用考试 | 必须存在 |
| `class_id` | 班级 | 引用班级 | 必须存在 |
| `applicable_subject_ids` | 适用科目集合 | 引用考试科目 | 至少一个；显式排除不适用科目 |
| `status` | 状态 | 有效/已移除 | 有任务后不可移除 |

- 业务唯一性：同一考试+班级唯一。
- 关联规则：任务只对适用科目生成；不适用科目不能用“全体缺考”代替。
- 删除规则：已有任务提交/通过/发布后不得移除；需先退回/撤回并审计。

### DR-EXAM-003 考试科目

- 概念：某场考试中某科目的满分、及格线、优秀线配置。
- 业务属性：

| 数据项 | 含义 | 格式/取值 | 约束 |
| --- | --- | --- | --- |
| `exam_subject_id` | 逻辑主键 | 代理键 | 唯一 |
| `exam_id` / `subject_id` | 考试/科目 | 引用 | 同一考试+科目唯一 |
| `full_score` | 满分 | 0.5 的倍数，>0 | 一位小数；P0 同考试科目对所有班同一满分 |
| `pass_percent` | 及格线百分比 | 0～100 | 默认 60 |
| `excellent_percent` | 优秀线百分比 | 0～100 | 默认 85；≥ 及格线 |
| `pass_score` / `excellent_score` | 计算后分数线 | 0.5 步长 | 百分比结果按 0.5 四舍五入 |

- 业务唯一性：同一考试+科目唯一。
- 关联规则：成绩校验上限、及格/优秀判定、统计口径都引用此配置；修改默认值不回溯历史考试。
- 删除规则：已有任务后不得改满分/线；需先退回/撤回。

## 5. 成绩数据

### DR-SCORE-001 成绩录入任务

- 概念：考试×班级×科目的录入/提交单元，记录第一责任人（班主任）和花名册快照。
- 业务属性：

| 数据项 | 含义 | 格式/取值 | 约束 |
| --- | --- | --- | --- |
| `task_id` | 逻辑主键 | 代理键 | 唯一 |
| `exam_id` / `class_id` / `subject_id` | 考试/班级/科目 | 引用 | 同一组合唯一 |
| `primary_teacher_id` | 第一责任人 | 引用班主任 | 生成时为班主任；快照保留 |
| `status` | 任务状态 | `TASK_DRAFT`/`TASK_SUBMITTED`/`TASK_RETURNED`/`TASK_APPROVED` | 只按状态机转换 |
| `version` | 版本 | 整数 | 乐观锁 |
| `roster_version` | 花名册快照版本 | 整数/标识 | 任务生成时固定 |
| `submitted_by` / `submitted_at` | 提交人/时间 | 引用用户/时间 | 提交时记录 |

- 业务唯一性：考试+班级+科目唯一。
- 关联规则：每个任务对应一组成绩记录；任务状态决定可编辑/可审核/可发布。
- 删除规则：任务不物理删除；不适用科目在生成前排除。

### DR-SCORE-002 成绩记录

- 概念：某学生某次考试某科目的结果，由“状态 + 数值”组成；缺考/未录入无值。
- 业务属性：

| 数据项 | 含义 | 格式/取值 | 约束 |
| --- | --- | --- | --- |
| `score_id` | 逻辑主键 | 代理键 | 唯一 |
| `task_id` | 所属任务 | 引用任务 | 必须存在 |
| `student_id` | 学生 | 引用学生 | 属于任务花名册 |
| `score_status` | 状态 | `SCORE_NORMAL`/`SCORE_ABSENT`/`SCORE_NOT_ENTERED` | 只能三态 |
| `score_value` | 分数 | 0～满分，0.5 倍数，一位小数 | 仅 NORMAL 有值；定点十进制 |
| `updated_by` / `updated_at` | 最后修改人/时间 | 引用用户/时间 | 审计 |
| `version` | 版本 | 整数 | 乐观锁 |

- 业务唯一性：同一任务+学生唯一。
- 关联规则：总分、排名、统计按状态和值计算；缺考/未录入不计入分母；真实 0 分是 NORMAL。
- 删除规则：提交后不物理删除；更正留痕。

### DR-PUB-001 班级成绩发布

- 概念：考试×班级的发布单元，控制学生可见性和版本。
- 业务属性：

| 数据项 | 含义 | 格式/取值 | 约束 |
| --- | --- | --- | --- |
| `publication_id` | 逻辑主键 | 代理键 | 唯一 |
| `exam_id` / `class_id` | 考试/班级 | 引用 | 同一组合唯一 |
| `status` | 状态 | `PUB_UNPUBLISHED`/`PUB_PUBLISHED`/`PUB_WITHDRAWN` | 只按状态机转换 |
| `version` | 版本 | 整数 | 初始 1；更正/重发 +1 |
| `published_by` / `published_at` | 发布人/时间 | 引用用户/时间 | 发布时记录 |
| `withdrawn_reason` | 撤回原因 | 文本 | 撤回时必填 |

- 业务唯一性：考试+班级唯一。
- 关联规则：只有 PUBLISHED 学生可见；发布条件是该班所有适用任务 APPROVED；撤回后不可见但数据保留。
- 删除规则：不物理删除；保留版本和审计。

## 6. 审计与 P1 复核

### DR-AUDIT-001 业务变更记录

- 概念：对成绩、任务、发布、撤回、更正、范围/归属变化等关键事件的只追加审计。
- 业务属性：

| 数据项 | 含义 | 格式/取值 | 约束 |
| --- | --- | --- | --- |
| `audit_id` | 逻辑主键 | 代理键 | 唯一、只追加 |
| `event_type` | 事件类型 | 成绩修改/提交/退回/通过/发布/撤回/更正/范围变化/归属变化/复核结论 | 枚举 |
| `entity_type` / `entity_id` | 对象类型/ID | 文本/代理键 | 指向业务对象 |
| `exam_id` / `class_id` / `subject_id` / `student_id` | 关联维度 | 引用/可空 | 按事件填写 |
| `before_value` / `after_value` | 前后值 | 文本/结构化快照 | 关键变更必填 |
| `reason` | 原因 | 文本 | 退回/撤回/更正/驳回必填 |
| `operator_id` / `operator_role` | 操作人/角色 | 引用用户/角色 | 必填 |
| `occurred_at` | 时间 | 时间戳 | 必填 |
| `source` | 来源 | 手工/导入/复核 | 必填 |
| `version` | 业务版本 | 整数 | 与发布/更正对应 |

- 业务唯一性：审计 ID 唯一；不提供业务界面修改/删除。
- 关联规则：与业务变更同事务；若依通用操作日志不能替代。
- 可见性：教务看业务审计；系统管理员看系统/安全元数据且成绩明细脱敏；班主任本班；学生不可见。

### DR-REVIEW-001 复核申请（P1）

- 概念：学生对本人已发布成绩的复查申请及处理记录。
- 业务属性：

| 数据项 | 含义 | 格式/取值 | 约束 |
| --- | --- | --- | --- |
| `review_id` | 逻辑主键 | 代理键 | 唯一 |
| `student_id` | 学生 | 引用学生 | 申请人本人 |
| `exam_id` / `subject_id` / `score_id` | 考试/科目/成绩 | 引用 | 同一考试+科目唯一活跃申请 |
| `reason` | 申请理由 | 文本 | 必填 |
| `status` | 状态 | `REV_PENDING`/`REV_PROCESSING`/`REV_NO_CHANGE`/`REV_CORRECTED`/`REV_REJECTED`/`REV_WITHDRAWN` | 只按状态机 |
| `handler_id` | 受理班主任 | 引用班主任 | 受理时记录 |
| `verification_opinion` | 班主任核查意见 | 无需修改/建议更正 + 依据 | 核查时记录 |
| `decision_reason` | 教务/驳回原因 | 文本 | 驳回/更正必填 |
| `created_at` / `updated_at` | 时间 | 时间戳 | 审计 |
| `deadline_at` | 申请截止 | 时间 | 发布后 5 个工作日（课程模拟，可配置） |

- 业务唯一性：同一学生+考试+科目存在活跃申请时禁止重复；终态后同一成绩版本不再受理。
- 关联规则：更正复用 `FR-PUB-004`；复核不改变 P0 发布状态机，只触发受控更正。
- 删除规则：不物理删除；保留状态和审计。

## 7. 账号与档案关联

### DR-AUTH-001 账号-角色-业务档案关联

- 概念：把若依登录账号、业务角色和学生/班主任业务档案关联起来，形成“登录身份→业务身份→数据范围”的逻辑链；不新建一套认证体系。
- 业务属性：

| 数据项 | 含义 | 格式/取值 | 约束 |
| --- | --- | --- | --- |
| `user_id` | 若依账号 | 引用 `sys_user` | 唯一；一个账号最多绑定一个学生或班主任 |
| `role_ids` | 业务角色集合 | 引用 `sys_role` | 至少一个；不含内置超级管理员 |
| `profile_type` | 档案类型 | 学生/班主任/无 | 与学生/班主任档案匹配 |
| `profile_id` | 业务档案 ID | 引用学生或班主任 | 一个档案最多绑定一个账号 |
| `bound_at` / `bound_by` | 绑定时间/操作人 | 时间/用户 | 审计 |
| `status` | 状态 | 有效/已解绑 | 停用账号不等于解绑 |

- 业务唯一性：账号与档案 1:1；一个账号只能属于一个学生或一个班主任。
- 关联规则：登录后按角色和数据范围解析；系统管理员/教务账号可无业务档案；学生/班主任账号必须有对应档案。
- 删除规则：解绑/停用不删除业务档案和历史成绩；审计保留。

## 8. 若依复用实体与边界

## 9. 数据一致性与完整性规则

| 规则 | 说明 |
| --- | --- |
| 成绩任务唯一 | 考试+班级+科目唯一；防止重复任务 |
| 成绩记录唯一 | 任务+学生唯一；防止重复分数 |

| 审计 | 关键变更只追加；与业务同事务 |
| P1 | 复核数据不改变 P0 成绩真值，只通过受控更正写入 |
