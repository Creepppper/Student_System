> 项目：高中学生信息与成绩管理系统  
> 基线：`BL-REQ-001 v1.2-provisional`  
> 文档版本：`v0.2-draft`  
> 状态：**第 2 阶段角色权限初稿（四角色版），待用户/小组审核**  
> 日期：2026-10-28  
> 说明：本文件把功能权限、数据范围和越权验收放在一起，确保与功能需求、用例、数据字典一致。  
> 关联：[03-角色与权限边界](../baseline/03-角色与权限边界.md) · [02-功能需求规格](02-功能需求规格.md)

## 0. 口径

1. **功能权限**决定“能不能进入某个功能/按钮”；**数据权限**决定“进入后能看/改哪些行”。两者必须同时成立。
2. 前端菜单/按钮隐藏只用于体验，不是安全边界；后端必须重新推导范围。
3. v1.2 起**教师端只保留班主任**：班主任负责本班全科成绩；教务独占审核/发布/撤回/更正；学生只看本人已发布成绩。
4. 已取消：`ROLE_TEACHER`、`SCOPE_ASSIGNED`、任教关系、按科目分配任课教师、任课教师复核核查。
5. 当前四类业务角色、权限配置和数据范围均未实现；若依只提供登录、JWT、RBAC、菜单、按钮权限、字典、日志等基础能力。

## 1. 角色定义

| 角色 ID | 名称 | 角色代码（建议） | 核心职责 | 默认数据范围 |
| --- | --- | --- | --- | --- |
| `ROLE_SYS_ADMIN` | 系统管理员 | `sys_admin` | 账号、角色、菜单、按钮、字典、系统参数、系统日志与安全管理 | `SCOPE_SYSTEM`；不参与成绩审批 |
| `ROLE_ACADEMIC` | 教务管理员 | `academic_admin` | 学年学期、年级班级、学生、班主任指派、科目、考试、审核发布、撤回、更正、全校统计与业务审计 | `SCOPE_ALL` |
| `ROLE_HEAD_TEACHER` | 班主任 | `head_teacher` | 本班学生信息、本班全科成绩录入/修改/提交、本班统计、P1 复核受理与核查 | `SCOPE_CLASS` |
| `ROLE_STUDENT` | 学生 | `student` | 本人允许信息、本人已发布成绩、总分与班级排名；P1 复核申请与结果查看 | `SCOPE_SELF` |

### 1.1 角色不是什么

- 系统管理员**不是**教务管理员，不默认拥有成绩明细查看、审核、发布、更正权；
- 班主任**不是**教务管理员，不能审核、发布、撤回或直接更正已发布成绩；
- 班主任只处理自己当前担任班主任的班级；
- 学生账号必须与唯一学生档案关联；
- 数据库、缓存、定时任务、Controller/Service 不是业务角色；
- **不存在任课教师角色**，也不存在按科目分配的任课教师数据范围。

## 2. 功能权限矩阵

图例：`F`=全部功能；`W`=授权范围内可写；`R`=授权范围内只读；`A`=审核/发布/撤回/最终确认；`S`=仅本人；`—`=无功能权限。

| 功能组 | 系统管理员 | 教务管理员 | 班主任 | 学生 |
| --- | --- | --- | --- | --- |
| 系统管理（账号/角色/菜单/参数） | F | — | — | — |
| 业务账号开通与档案关联 | W | W | — | — |
| 学年、学期、年级、班级管理 | — | F | R（本班） | — |
| 学生档案 | — | F | R（本班学生） | S（本人允许字段） |
| 班主任档案、科目 | R | F | R（本人） | — |
| 考试管理 | — | F | R（本班考试） | — |
| 成绩录入与提交 | — | R（全校监督） | W（本班全科） | — |
| 成绩审核、发布、撤回、更正 | — | A | R（本班状态） | — |
| 学生成绩查询（本人） | — | — | — | S（本人已发布） |
| 基础统计 | — | R（全校） | R（本班汇总） | —（个人成绩见查询） |
| 业务变更记录 | R（系统审计，脱敏） | R（业务审计） | R（本班相关） | — |
| P1 成绩复核 | — | A（最终确认） | W（本班受理/核查） | W（本人申请/查看） |
| P1 Excel 导入导出 | — | R（全校导出） | W（本班导入）/R（本班导出） | — |
| P1 成绩趋势 | — | R（全校） | R（本班） | S（本人） |
| P1 班级对比 | — | R（全校） | R（授权班级） | — |

### 2.1 关键说明

- **成绩录入**：只有班主任拥有本班全科 `W`；教务是 `R`，用于监督和审核，不直接改分；其他班主任不能编辑本班以外成绩。
- **审核发布**：只有教务拥有 `A`；班主任只能看状态；系统管理员没有 `A`。
- **发布后更正**：只有教务发起；班主任不能直接覆盖已发布成绩。
- **P1 复核**：班主任受理并核查，教务最终确认/更正；学生只看本人。
- **业务变更记录**：系统管理员只看系统/安全审计元数据，成绩字段脱敏，不能展开/导出成绩明细。

## 3. 数据权限矩阵

### 3.1 数据范围代码

| 范围代码 | 适用角色 | 过滤规则 | 典型数据 |
| --- | --- | --- | --- |
| `SCOPE_SYSTEM` | 系统管理员 | 仅系统管理表、账号/角色/菜单/配置/系统日志 | 用户、角色、菜单、参数；不含成绩明细 |
| `SCOPE_ALL` | 教务管理员 | 全校教务数据 | 所有班级、学生、班主任、考试、成绩、统计 |
| `SCOPE_CLASS` | 班主任 | 本人当前担任班主任的班级 | 本班学生、本班全科成绩、本班考试、本班复核 |
| `SCOPE_SELF` | 学生 | `student_id = 当前账号关联学生`，且成绩已发布 | 本人成绩、本人允许信息、本人复核 |

### 3.2 范围细则

| 规则 | 说明 |
| --- | --- |
| 班主任只处理本班 | 不能查看/修改其他班级学生、任务、成绩、统计或复核 |
| 班主任本班全科可写 | 可录入/修改本班全科；提交后锁定；可查看本班全科汇总；审核/发布/更正仍归教务 |
| 教务看全校但改分受控 | 可查看全校；修改必须走审核退回或发布后更正，不能静默改值 |
| 学生只看本人已发布 | 未发布/已撤回/他人成绩一律不可见；不能通过改 ID/导出/统计绕过 |
| 系统管理员不看成绩明细 | 系统审计日志中的成绩字段脱敏；不能通过日志展开/导出成绩明细 |
| 历史数据不因关系变化消失 | 班主任更换、学生转班/毕业后，历史成绩保留；编辑权限按当前班级关系授予 |

## 4. 角色组合与有效权限

| 组合 | 有效功能权限 | 有效数据范围 | 备注 |
| --- | --- | --- | --- |
| 教务 + 班主任 | 教务审批 + 本班全科录入/查看 | 全校 ∪ 本班 | 不得审核自己作为班主任提交的任务 |
| 系统管理员 + 教务 | 系统管理 + 教务审批 | 系统范围 ∪ 全校教务 | 不推荐日常共用；若共用，审批用教务身份并留痕 |
| 班主任 + 学生 | 不推荐 | 本班 ∪ 本人 | 同一账号不应同时是班主任和学生 |

### 4.1 防止叠加越权

1. 功能权限取并集，数据范围取并集，但每条数据仍必须落在至少一个业务关系内。
2. 不能因为拥有 `SCOPE_ALL` 就自动获得“修改成绩”的功能权限；功能与数据必须同时满足。
3. 不能因为拥有 `ROLE_ACADEMIC` 就自动获得系统管理权限。
4. 任何“审核自己作为班主任提交的任务/确认自己申请的复核更正”的路径都必须被禁止。
5. “审核”包括通过和退回；即使拥有 `SCOPE_ALL`/`A`，也不得对自己提交的任务执行通过或退回。
6. 复核确认/更正不得由申请人本人或该班班主任完成；系统按任务提交人、实际操作人和申请人逐项比对，命中即拒绝。

## 5. 若依复用边界

| 若依能力 | 是否复用 | 本项目用法 | 注意事项 |
| --- | --- | --- | --- |
| 登录、验证码、JWT | 复用 | 统一入口；不另建学生登录 | 令牌只证明登录态，不证明数据权限 |
| 用户、角色、菜单、按钮权限 | 复用 | 四类业务角色 + `business:*` 权限字符串 | 不把业务角色写死在前端 |
| 密码策略、账号启停 | 复用 | 学生/班主任账号由管理员开通 | 停用不删除业务档案 |
| 部门树 `sys_dept` | 部分复用 | 内部组织展示/辅助授权 | 不把年级/班级直接等同于部门树 |
| 数据权限机制 | 部分复用 | 复用机制，业务范围在服务/查询中实现 | 默认按部门，不能直接表达“本班/本人” |
| 字典 | 复用 | 考试类型、状态显示 | 状态机核心用稳定常量，字典只做展示 |
| 操作日志 | 复用 | 接口/登录/异常 | 不能替代业务变更记录的前后值 |
| Excel 工具 | P1 复用 | 导入导出 | 必须预检、事务、权限过滤 |
| 代码生成器 | 复用（辅助） | CRUD 骨架后人工审查 | 不生成状态机/权限/业务规则 |
| OpenAPI/Swagger | 复用 | 接口文档 | 文档不能替代权限测试 |

## 7. 越权验收矩阵

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| `AC-AUTH-01` | 学生 A 请求学生 B 成绩 ID | 403/404，不返回 B 数据 |
| `AC-AUTH-02` | 班主任请求非本班任务/成绩 | 403，不能改 `classId` 绕过 |
| `AC-AUTH-03` | 班主任查看/修改本班全科 | 允许；其他班级被拒绝 |
| `AC-AUTH-04` | 班主任尝试审核/发布/更正 | 403；只能看状态 |
| `AC-AUTH-05` | 系统管理员尝试审核/发布 | 403；系统管理权限不等于教务审批 |
| `AC-AUTH-06` | 教务直接改已发布成绩 | 只能走更正流程，必须填原因并留痕 |
| `AC-AUTH-07` | 班主任更换后原班主任访问 | 拒绝编辑；新班主任按本班范围可编辑；历史保留 |
| `AC-AUTH-08` | 统计/导出接口传超范围参数 | 后端按当前账号范围过滤，不返回超范围数据 |
| `AC-AUTH-09` | 前端隐藏按钮但直接调接口 | 后端仍返回 403 |
| `AC-AUTH-10` | 一人多角色审核自己提交的任务 | 被拒绝；无法满足时记录课程简化 |
| `AC-AUTH-11` | 系统管理员查看业务审计 | 只看到脱敏元数据，不能展开/导出成绩明细 |
| `AC-AUTH-12` | 班主任变更后历史成绩责任人 | 历史任务第一责任人快照不变；新操作留痕 |

## 8. 一致性检查

- [x] 四类角色都有明确职责和不做什么；
- [x] 每个 `W`/`A` 功能都有对应数据范围；
- [x] 班主任本班全科 `W` 与教务 `A` 已区分；
- [x] 审核/发布/更正仍只归教务；
- [x] 学生范围严格为本人且已发布；
- [x] 系统管理员不被授予教务审批权，也不默认看成绩明细；
- [x] 自审禁止与多角色账号一致；
- [x] 前端隐藏不被当作安全措施；
- [x] 任课教师角色、`SCOPE_ASSIGNED`、任教关系已退出有效权限；
- [x] 未把若依已有能力写成业务模块已实现。
