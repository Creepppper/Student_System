## 0. 说明

1. 用例角色、数据范围和状态名以基线 `BL-REQ-001 v1.2-provisional` 为准。
2. 本文不描述 Controller、Service、数据库表或页面组件；主事件流描述“谁在什么条件下做什么，系统给出什么可观察结果”。
3. `D-003` 按 v1.2：**班主任可录入/修改本班全科；不设任课教师；审核/发布/更正仍只由教务执行**。
4. P1 用例标记 `【P1】`，不进入 P0 退出条件。
5. 用例中的“班主任”指本班当前班主任；班主任只能处理自己当前担任班主任的班级。

## 1. 支持用例

### UC-AUTH-001 登录与权限校验（支持用例）

- 目标：合法账号进入系统，获得与角色相符的功能和数据范围。
- 主要参与者：四类角色。
- 触发：用户打开登录页并提交凭据。
- 前置条件：账号存在且启用；验证码服务可用；账号已绑定必要的业务档案（学生/班主任）。
- 主事件流：
  1. 用户输入用户名、密码、验证码。
  2. 系统校验验证码、账号状态和密码。
  3. 系统生成令牌，加载角色、菜单/按钮权限和业务数据范围。
  4. 用户进入工作台；后续每次业务请求由后端校验功能权限和数据范围。
- 备选事件流：
  - 1a. 验证码错误/过期：拒绝登录并刷新验证码。
  - 2a. 账号停用：统一提示登录失败，不泄露账号是否存在。
  - 2b. 账号未绑定学生/班主任档案：可登录管理端但业务功能按角色拒绝。
- 异常事件流：缓存/令牌服务不可用→拒绝登录并提示稍后重试，不放行。
- 后置条件：成功时建立会话；失败时无会话；登录/失败均记录日志。
- 关联需求：`FR-AUTH-001`～`FR-AUTH-005`。
- 关联规则：`BR-AUTH-001`、`BR-AUTH-002`、`BR-AUTH-010`、`BR-AUTH-011`、`BR-STU-006`、`BR-TCH-007`。

### UC-ORG-001 维护学年、学期、年级与班级（支持用例）

- 目标：建立学校组织与学年结构，为班级归属、考试和班主任任职提供基础。
- 主要参与者：教务管理员。
- 触发：新学期开学前或组织调整时。
- 前置条件：教务管理员已登录；学年/年级基础信息已确定。
- 主事件流：
  1. 教务创建学年并设置当前学年。
  2. 教务创建第一/第二学期。
  3. 教务维护年级层次与排序。
  4. 教务创建班级，指定学年、年级、班号和班主任。
  5. 系统校验唯一性和引用关系，记录审计。
- 备选事件流：
  - 4a. 班主任未确定：允许先建班后指派，但开放考试前必须补齐。
  - 4b. 班级已有学生/成绩：不物理删除，改为归档。
- 异常事件流：编码重复、日期越界、跨学年复用班级→拒绝并提示。
- 后置条件：班级可被学生归属、考试范围和班主任任职引用；班主任获得本班数据范围。
- 关联需求：`FR-ORG-001`～`FR-ORG-005`。
- 关联规则：`BR-ORG-001`～`BR-ORG-010`。

### UC-AUDIT-001 查询业务变更记录（支持用例）

- 目标：按权限查看成绩、任务、发布、更正等关键变更，支持追溯。
- 主要参与者：教务管理员、系统管理员、班主任。
- 触发：需要核查成绩变更、发布历史或争议处理。
- 前置条件：已登录；存在审计记录；操作人具备查看范围。
- 主事件流：
  1. 用户按考试/班级/科目/学生/时间筛选。
  2. 系统按角色范围返回审计元数据（事件、前后值、原因、操作人、时间、版本）。
  3. 用户查看详情；系统对系统管理员隐藏成绩明细，仅显示脱敏元数据。
- 备选事件流：无记录→返回空列表并提示；越权→403。
- 异常事件流：审计记录不可修改/删除；查询失败→提示重试，不显示猜测数据。
- 后置条件：不改变业务数据；查询行为可按需记录。
- 关联需求：`FR-AUDIT-001`、`FR-AUDIT-002`。
- 关联规则：`BR-AUDIT-001`～`BR-AUDIT-008`。

## 2. P0 核心用例

### UC-STU-001 维护学生档案与班级归属

- 用例 ID / 名称：`UC-STU-001` / 维护学生档案与班级归属
- 目标：建立/维护学生最小档案，按学年记录班级归属，支持转班、毕业和历史追溯。
- 主要参与者：教务管理员。
- 次要参与者：学生（只读本人允许字段）、系统管理员（账号开通）。
- 触发：新生入学、转班、休学/复学、毕业或档案更正。
- 前置条件：学年、班级、年级已存在；操作人具备学生档案权限。
- 主事件流：
  1. 教务查询/新增学生，录入学号、姓名、性别（可选）、入学年份。
  2. 系统校验学号全校唯一、必填项完整。
  3. 教务为学生建立本学年班级归属。
  4. 系统校验同一学年只有一条有效归属，记录归属历史。
  5. 需要登录时，系统管理员/教务开通账号并绑定学生档案。
  6. 系统记录档案、归属、账号绑定审计。
- 备选事件流：
  - 3a. 转班：先结束旧归属，再建立新归属；历史成绩仍归属考试时班级。
  - 5a. 暂不开通账号：允许先建档，后续开通。
  - 6a. 学生毕业/转出：状态变更，账号可停用，历史数据保留。
- 异常事件流：
  - 学号重复→拒绝保存。
  - 同一学年重复有效归属→拒绝。
  - 有成绩学生物理删除→拒绝。
  - 已提交/发布任务下变更归属→先退回/撤回。
- 后置条件：学生档案和归属可查；学生账号（如开通）只能看本人；历史归属/成绩保留。
- 关联需求：`FR-STU-001`～`FR-STU-004`、`FR-AUTH-003`。
- 关联规则：`BR-STU-001`～`BR-STU-009`、`BR-ORG-008`。

### UC-TCH-001 维护班主任档案与科目

- 用例 ID / 名称：`UC-TCH-001` / 维护班主任档案与科目
- 目标：建立班主任必要档案和可配置科目；班主任与班级关系由 `UC-ORG-001` 维护，本用例不建立按科目分配的授权关系。
- 主要参与者：教务管理员。
- 次要参与者：班主任（只读本人信息）、系统管理员（账号关联）。
- 触发：新学期、班主任调整或科目调整。
- 前置条件：班主任尚未建立重复档案；科目编码/名称未重复。
- 主事件流：
  1. 教务维护班主任工号、姓名、状态。
  2. 教务维护科目编码、名称、排序、状态。
  3. 班主任与班级的指派/变更走 `UC-ORG-001`；本用例只校验班主任在职。
  4. 系统校验工号/科目唯一，记录档案与科目变更审计。
- 备选事件流：
  - 1a. 班主任同时担任多个班班主任：允许，但每班同一时刻只有一名有效班主任。
  - 2a. 科目停用：不影响历史考试和成绩。
- 异常事件流：工号/科目重复、停用班主任被指派、归档班级→拒绝；有任务/成绩的班主任不得物理删除。
- 后置条件：班主任档案可查；科目可被考试引用；不产生按科目授权关系。
- 关联需求：`FR-TCH-001`、`FR-TCH-002`；班主任指派见 `FR-ORG-005`。
- 关联规则：`BR-TCH-001`、`BR-TCH-006`、`BR-TCH-007`、`BR-SUB-001`～`BR-SUB-003`。

### UC-EXAM-001 创建考试并设置适用科目

- 用例 ID / 名称：`UC-EXAM-001` / 创建考试并设置适用科目
- 目标：创建一次考试，配置参与班级、每班适用科目、满分/及格线/优秀线，并开放录入。
- 主要参与者：教务管理员。
- 次要参与者：班主任（接收任务）。
- 触发：月考/期中/期末等考试安排确定后。
- 前置条件：学年/学期、班级、科目已存在；考试类型字典可用。
- 主事件流：
  1. 教务创建考试（名称、类型、学年、学期、日期）。
  2. 系统校验名称在同一学年+学期唯一、日期合法，状态为 `EXAM_DRAFT`。
  3. 教务选择参与班级，并为每班配置适用科目；不适用科目显式排除。
  4. 教务为每个考试科目配置满分、及格线百分比、优秀线百分比。
  5. 系统校验满分 > 0 且为 0.5 的倍数、百分比合法、优秀线 ≥ 及格线。
  6. 教务将考试从 `EXAM_DRAFT` 开放为 `EXAM_OPEN`。
  7. 系统按“考试×班级×适用科目”生成成绩任务，记录班主任第一责班级任职师、班主任和花名册。
- 备选事件流：
  - 3a. 只部分班级参加：允许，范围显式配置。
  - 3b. 某班不考某科：显式排除，不生成该科任务，不用“全体缺考”代替。
  - 5a. 分数精度：0.5 分步长、一位小数；满分/线也按 0.5 步长。
  - 6a. 缺班主任/花名册为空：阻止开放并提示先补齐。
- 异常事件流：
  - 名称重复/日期倒置→拒绝。
  - 已有任务后移除班级/科目/改满分→拒绝，需先退回/撤回。
  - 归档时有草稿/已提交/已退回任务→拒绝。
- 后置条件：考试为 `EXAM_OPEN`；任务为 `TASK_DRAFT`；班主任可进入录入。
- 关联需求：`FR-EXAM-001`～`FR-EXAM-004`、`FR-SCORE-001`。
- 关联规则：`BR-EXAM-001`～`BR-EXAM-012`、`BR-SCORE-001`、`BR-SCORE-003`。

### UC-SCORE-001 录入与暂存成绩

- 用例 ID / 名称：`UC-SCORE-001` / 录入与暂存成绩
- 目标：班主任录入本班全科，支持逐生暂存、缺考标记和进度查看。
- 主要参与者：班主任。
- 次要参与者：教务管理员（只读监督）。
- 触发：考试开放后，班主任进入任务录入成绩。
- 前置条件：任务为 `TASK_DRAFT`/`TASK_RETURNED`；考试为 `EXAM_OPEN`；操作人是本班班主任。
- 主事件流：
  1. 班主任打开任务，系统显示学生花名册、满分、0.5 分步长和已录入进度。
  2. 班主任逐个学生录入分数，或显式标记缺考。
  3. 系统校验学生属于花名册、分数 0～满分、0.5 倍数、一位小数、缺考无数值。
  4. 班主任点击“保存草稿”；系统保存并保持 `SCORE_NOT_ENTERED` 未填项。
  5. 系统显示已录入/缺考/未录入数量；记录修改人。
- 备选事件流：
  - 2a. 学生缺考：显式标记 `SCORE_ABSENT`，不填分数。
  - 2b. 真实 0 分：保存 `SCORE_NORMAL` + 0。
  - 4a. 并发修改：版本号冲突时拒绝覆盖，提示刷新。
- 异常事件流：
  - 非本班班主任→403。
  - 任务已提交/通过/发布→拒绝编辑。
  - 分数非法/缺考带分数/重复学生→字段级错误，不保存该项。
- 后置条件：草稿保存；任务仍为 `TASK_DRAFT`/`TASK_RETURNED`；未录入项保留。
- 关联需求：`FR-SCORE-001`～`FR-SCORE-003`、`FR-SCORE-005`。
- 关联规则：`BR-SCORE-002`～`BR-SCORE-005`、`BR-SCORE-008`、`BR-SCORE-009`、`BR-SCORE-013`～`BR-SCORE-016`。

### UC-SCORE-002 提交成绩任务

- 用例 ID / 名称：`UC-SCORE-002` / 提交成绩任务
- 目标：把完整任务原子提交给教务审核，提交后锁定；退回后可修改重提。
- 主要参与者：班主任。
- 次要参与者：教务管理员（审核）。
- 触发：班主任完成本任务录入后点击“提交”。
- 前置条件：任务为 `TASK_DRAFT`/`TASK_RETURNED`；考试为 `EXAM_OPEN`；操作人授权；版本号已知。
- 主事件流：
  1. 班主任点击提交，系统检查任务内无 `SCORE_NOT_ENTERED`。
  2. 系统校验所有分数合法、版本号匹配、考试为开放。
  3. 系统原子更新任务为 `TASK_SUBMITTED`，写入提交人、角色、时间、成绩快照。
  4. 系统锁定任务，班主任只读；教务可审核。
- 备选事件流：
  - 1a. 有未录入：拒绝提交，列出未录入学生。
  - 3a. 版本冲突：拒绝提交，提示刷新后重试。
  - 4a. 教务退回：任务变 `TASK_RETURNED`，班主任可修改并重提。
- 异常事件流：考试非 `EXAM_OPEN`→拒绝；非授权→403；重复提交→拒绝/幂等提示。
- 后置条件：任务 `TASK_SUBMITTED`；班主任不能自行撤回；提交记录可审计。
- 关联需求：`FR-SCORE-004`。
- 关联规则：`BR-SCORE-006`～`BR-SCORE-008`、`BR-PUB-001`、`BR-PUB-013`。

### UC-PUB-001 教务审核与退回

- 用例 ID / 名称：`UC-PUB-001` / 教务审核与退回
- 目标：教务逐任务审核成绩，通过或退回并留下原因，确保发布前有独立复核。
- 主要参与者：教务管理员。
- 次要参与者：班主任（接收退回/通过状态）。
- 触发：任务进入 `TASK_SUBMITTED` 后。
- 前置条件：任务为 `TASK_SUBMITTED`；审核人不是该任务的实际录入/提交人。
- 主事件流：
  1. 教务打开待审核任务，查看花名册、分数、缺考、进度和变更记录。
  2. 教务选择“通过”或“退回”。
  3. 通过：任务变 `TASK_APPROVED`；退回：必须填写原因，任务变 `TASK_RETURNED`。
  4. 系统记录审核人、角色、时间、原因；班主任看到结果。
- 备选事件流：
  - 2a. 发现问题但只需小改：退回并说明具体学生/科目。
  - 3a. 通过后发布前发现错误：教务可退回（发布未发布时），任务回到 `TASK_RETURNED`。
- 异常事件流：
  - 自审→拒绝。
  - 退回原因空→拒绝。
  - 任务非 `TASK_SUBMITTED`→拒绝。
  - 已发布任务退回→必须先撤回。
- 后置条件：任务通过或退回；审核记录可查；通过任务可参与班级发布。
- 关联需求：`FR-PUB-001`。
- 关联规则：`BR-PUB-001`～`BR-PUB-003`、`BR-PUB-013`、`BR-AUTH-012`。

### UC-PUB-002 按班级发布成绩

- 用例 ID / 名称：`UC-PUB-002` / 按班级发布成绩
- 目标：把某班某场考试的全部适用科目成绩发布给学生，发布前校验完整性。
- 主要参与者：教务管理员。
- 次要参与者：学生（发布后可见）、班主任（看状态）。
- 触发：某班所有适用科目任务已通过，教务决定发布。
- 前置条件：该班所有适用科目任务 `TASK_APPROVED`；无 `SCORE_NOT_ENTERED`；至少 1 个适用科目；发布人授权。
- 主事件流：
  1. 教务选择考试和班级，查看发布前检查结果。
  2. 系统校验所有适用任务已通过、无未录入、范围非空。
  3. 教务确认发布；系统创建 `PUB_PUBLISHED`，版本 1。
  4. 系统记录发布人、时间、范围、版本；学生立即可见。
- 备选事件流：
  - 1a. 有科目未通过：阻止发布并列出科目。
  - 1b. 有未录入：阻止发布并列出学生。
  - 4a. 重复发布：幂等提示，不产生重复版本。
- 异常事件流：适用科目为 0→拒绝；非教务→403；发布过程中版本冲突→拒绝并提示重试。
- 后置条件：班级发布 `PUB_PUBLISHED`；学生可见；任务锁定；发布记录生成。
- 关联需求：`FR-PUB-002`。
- 关联规则：`BR-PUB-004`、`BR-PUB-005`、`BR-PUB-011`、`BR-PUB-012`、`BR-CALC-002`。

### UC-QUERY-001 学生查询已发布成绩

- 用例 ID / 名称：`UC-QUERY-001` / 学生查询已发布成绩
- 目标：学生按学年/学期/考试类型查询本人已发布成绩、总分和班级排名。
- 主要参与者：学生。
- 次要参与者：教务/班主任（仅支持排障，不代替学生查询）。
- 触发：学生登录后打开成绩查询。
- 前置条件：学生账号已绑定档案；该班该考试 `PUB_PUBLISHED`。
- 主事件流：
  1. 学生进入成绩查询，默认显示最近一次已发布考试。
  2. 系统按学年/学期/考试类型筛选，只返回本人已发布数据。
  3. 系统展示各科分数（一位小数）或“缺考”、总分（完整时）、班级排名（完整时）。
  4. 学生查看考试详情；缺考显示“缺考”，不显示 0。
- 备选事件流：
  - 3a. 总分不完整：显示“不完整（缺考/未录入）”，不显示数值总分/排名。
  - 3b. 无已发布成绩：提示“暂无成绩记录”。
  - 3c. 已撤回：显示“成绩已撤回/暂不可用”，不显示旧值。
- 异常事件流：
  - 未登录→401。
  - 访问他人成绩→403/404。
  - 参数扩大范围→按本人过滤或拒绝。
- 后置条件：不改变成绩；学生只看到本人数据；查询可按需记录。
- 关联需求：`FR-QUERY-001`、`FR-QUERY-002`。
- 关联规则：`BR-QUERY-001`～`BR-QUERY-009`、`BR-CALC-001`～`BR-CALC-003`、`BR-AUTH-002`。

### UC-PUB-003 教务更正已发布成绩

- 用例 ID / 名称：`UC-PUB-003` / 教务更正已发布成绩（含撤回）
- 目标：发布后发现单点或系统性错误时，由教务受控更正或撤回，保留版本和审计。
- 主要参与者：教务管理员。
- 次要参与者：班主任（提供依据）、学生（看到更新/不可见）。
- 触发：发布后发现录入错误、核分错误或学生复核成立（P1 复用）。
- 前置条件：班级发布为 `PUB_PUBLISHED`；更正原因、前后值明确；操作人为教务。
- 主事件流：
  1. 教务定位成绩记录，选择“更正”或“撤回发布”。
  2. 单点更正：填写新值/状态、原因；系统校验合法性。
  3. 系统更新成绩，记录前后值、原因、操作人、版本 +1，重算总分/排名。
  4. 学生查询显示更新后的成绩；发布状态仍为 `PUB_PUBLISHED`。
  5. 撤回发布：填写原因；状态变 `PUB_WITHDRAWN`；学生立即不可见；数据保留。
  6. 系统性错误：撤回→退回相关任务→更正→重审→重新发布，版本递增。
- 备选事件流：
  - 2a. 只改单科：不撤回整班，按单点更正。
  - 4a. 撤回后重新发布：所有适用任务再次 `TASK_APPROVED`，版本 +1。
  - 5a. 撤回后学生访问：显示“已撤回/暂不可用”。
- 异常事件流：
  - 非教务→403；原因空→拒绝；新值非法→拒绝；版本冲突→拒绝。
  - 该班班主任直接改已发布成绩→拒绝。
  - 逐条静默改系统性错误→禁止。
- 后置条件：成绩/发布版本更新；审计完整；学生可见性正确；历史版本可追溯。
- 关联需求：`FR-PUB-003`、`FR-PUB-004`、`FR-AUDIT-002`。
- 关联规则：`BR-PUB-006`～`BR-PUB-010`、`BR-PUB-014`、`BR-CALC-001`～`BR-CALC-003`、`BR-AUDIT-001`。

### UC-STAT-001 基础成绩统计

- 用例 ID / 名称：`UC-STAT-001` / 基础成绩统计
- 目标：为教务/班主任提供单场考试、单班、单科或班级总分排名的可解释统计。
- 主要参与者：教务管理员、班主任。
- 次要参与者：无。
- 触发：考试发布后或审核通过后需要分析。
- 前置条件：用户具备对应范围；考试/班级/科目存在；满分/线已配置。
- 主事件流：
  1. 用户选择考试、班级、科目（或班级总分）。
  2. 系统按范围校验并读取已通过/已发布成绩。
  3. 系统按 `SCORE_NORMAL` 计算有效人数、平均/最高/最低、及格率、优秀率、分数段；缺考/未录入单列。
  4. 班级总分排名只统计完整总分，按 1,2,2,4 竞争排名。
  5. 页面显示口径说明（分母、缺考处理、满分、线）。
- 备选事件流：
  - 3a. 无有效成绩：显示“无有效成绩”，不显示 0%。
  - 4a. 不完整学生：单列并注明原因，不参与排名。
  - 5a. 不同满分：分科或归一化，不直接混算。
- 异常事件流：越权→403；无数据→提示；跨考试/多班对比→P0 不支持。
- 后置条件：统计结果可复现；不改变成绩真值；统计口径可解释。
- 关联需求：`FR-STAT-001`、`FR-STAT-002`。
- 关联规则：`BR-STAT-001`～`BR-STAT-010`、`BR-CALC-003`～`BR-CALC-009`。

## 3. P1 用例

### UC-REVIEW-001 成绩复核【P1】

- 用例 ID / 名称：`UC-REVIEW-001` / 成绩复核
- 优先级：**P1**（不阻塞 P0）
- 目标：学生对本人已发布成绩申请复核，班主任受理并核查，教务最终确认和更正。
- 主要参与者：学生。
- 次要参与者：班主任、教务管理员。
- 触发：学生对某科已发布成绩有疑问。
- 前置条件：成绩 `PUB_PUBLISHED`；在发布后 5 个工作日内（课程模拟，可配置）；同一考试+科目无活跃申请。
- 主事件流：
  1. 学生选择考试+科目，填写理由，提交复核申请（`REV_PENDING`）。
  2. 班主任查看本班申请，受理或驳回；驳回必须填原因。
  3. 受理后进入 `REV_PROCESSING`；班主任对本班申请提交“无需修改/建议更正”的核查意见及依据。
  4. 教务确认：无需修改→`REV_NO_CHANGE`；更正→`REV_CORRECTED`，复用 `FR-PUB-004` 记录前后值/原因/版本；驳回→`REV_REJECTED`。
  5. 学生查看状态、处理意见和更正后的成绩。
- 备选事件流：
  - 1a. 学生在受理前撤回→`REV_WITHDRAWN`。
  - 4a. 班级发布已撤回：复核可继续，更正结果在重新发布后可见。
- 异常事件流：
  - 他人成绩/未发布/超时/重复活跃申请→拒绝。
  - 班主任非本班→403。
  - 申请人或本班班主任尝试做最终确认→拒绝。
- 后置条件：复核状态明确；更正留痕；学生可见结果；P0 发布/审计不受破坏。
- 关联需求：`FR-REVIEW-001`、`FR-REVIEW-002`、`FR-REVIEW-004`、`FR-REVIEW-005`。
- 关联规则：`BR-REVIEW-001`～`BR-REVIEW-012`、`BR-PUB-009`、`BR-AUTH-012`。

### UC-IMPORT-001 成绩导入导出【P1】

- 目标：按任务生成模板，预检后事务导入；按权限导出。
- 参与者：班主任、教务。
- 前置条件：任务为 `TASK_DRAFT`/`TASK_RETURNED`；用户有范围权限。
- 主事件流：下载模板→填写→预检（行号/学号/原因）→修正→事务导入→审计。
- 备选/异常：有错误不部分写入；已提交/发布任务拒绝导入；版本冲突拒绝；导出按范围过滤并留痕。
- 后置条件：任务数据更新或完全不变；审计完整。
- 关联需求：`FR-IMPORT-001`～`FR-IMPORT-004`；规则：`BR-IMP-001`～`BR-IMP-008`。

### UC-TREND-001 成绩趋势【P1】

- 目标：按同口径查看学生个人或授权班级/科目的跨考试趋势。
- 参与者：学生、班主任、教务。
- 前置条件：多次已发布考试；同科目/同满分口径。
- 主事件流：选择范围→系统取已发布数据→按得分率/指标绘图→显示口径。
- 备选/异常：口径不同→拒绝或提示；无数据→提示；越权→403。
- 后置条件：只读；不预测；不改变成绩。
- 关联需求：`FR-TREND-001`、`FR-TREND-002`；规则：`BR-STAT-007`、`BR-CALC-009`。

### UC-COMPARE-001 多班级对比【P1】

- 目标：同一考试、同一科目、同一满分口径下对比授权班级指标。
- 参与者：教务、班主任（授权班级）。
- 前置条件：同考试同科目同口径；用户有范围权限。
- 主事件流：选择考试/科目/班级→系统按已发布数据计算指标→展示对比与口径。
- 备选/异常：跨口径→拒绝；越权→403；不做班级“好坏”评价。
- 后置条件：只读；不改变成绩。
- 关联需求：`FR-COMPARE-001`；规则：`BR-STAT-007`、`BR-STAT-010`。
