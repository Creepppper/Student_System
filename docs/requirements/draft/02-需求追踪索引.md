## 4. 追踪缺口与处理

| 缺口 | 处理 |
| --- | --- |
| P1 的 11 项功能只做摘要追踪，不细化到页面/接口 | 符合“P1 不阻塞 P0”的边界；进入 P1 实现前再细化 |
| 组织/账号类后台功能没有独立详细用例 | 由 `UC-ORG-001`、`UC-AUTH-001` 支持用例覆盖，主验收仍逐条存在 |
| 图表/原型/接口尚未建立 | 本阶段不绘图、不写接口；后续阶段再补追踪 |
| NFR 指标多为课程实验建议目标 | 未实测，见 NFR 文档的“测量条件/验收方式” |

## 5. 一致性规则

1. 一个 FR 只能属于一个优先级；P0 的 35 项不出现 P1 行。
2. 每个 P0 FR 至少有一个 `AC-<FR>` 和一个主要 `BR-*`。
3. 每个用例至少追踪到一个 P0 FR；P1 用例单独标记。
4. 数据需求与业务规则使用同一术语；出现差异以 `04-核心业务规则.md` 为准。
