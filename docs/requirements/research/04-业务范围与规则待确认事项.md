# 业务范围与规则待确认事项

> 状态：需求访谈问题清单。表中“建议默认值”仅用于推动讨论，不代表已确认需求。

## 1. 最高优先级决策

| ID | 待确认问题 | 为什么必须确认 | 建议默认值 |
| --- | --- | --- | --- |
| Q-001 | 系统面向单所高中还是可配置多校？ | 决定所有数据是否需要学校维度 | 单所高中，不做多租户 |
| Q-002 | 首期角色究竟有哪些？ | 决定用例和数据权限 | 系统管理员、教务管理员、任课教师、班主任、学生 |
| Q-003 | 家长是否为首期用户？ | 涉及监护关系、隐私和账号绑定 | 不纳入首期 |
| Q-004 | 任课教师与班主任的成绩权限如何划分？ | 防止班主任或科任教师越权改分 | 科任教师录入本人科目；班主任只看本班汇总并协助复核 |
| Q-005 | 审核／发布按整场考试、年级、班级还是科目？ | 决定状态实体和并发粒度 | 按“考试 × 班级”提交和审核，整场考试可汇总查看 |
| Q-006 | 发布后的成绩是否允许直接修改？ | 决定审计和版本模型 | 禁止直接覆盖；通过复核或教务纠错流程改动并留痕 |
| Q-007 | 学生能看到班级排名、年级排名和他人分数吗？ | 涉及隐私和排名计算 | 只看本人分数与经批准展示的本人名次，不显示同学明细 |
| Q-008 | 缺考、作弊、缓考如何记录？ | “缺考=0”会扭曲统计 | 分数与考试状态分离；是否计入统计另设规则 |
| Q-009 | 实验一必须提交哪些具体文件和图？ | 当前缺少原始实验一任务书 | 补取老师原文件后再冻结图表清单 |

## 2. 组织与人员规则

| ID | 待确认问题 | 建议讨论点 |
| --- | --- | --- |
| Q-010 | 学年、学期、年级、班级如何编码？ | 名称唯一范围、起止日期、是否保留历史 |
| Q-011 | 学生转班、留级、毕业后如何处理？ | 不能仅覆盖当前 `class_id`；是否保留班级归属历史 |
| Q-012 | 学号在全校永久唯一，还是按届唯一？ | 决定唯一索引与归档规则 |
| Q-013 | 教师工号是否唯一？教师可否跨年级、跨班、跨科任教？ | 决定任教关系模型 |
| Q-014 | 一个班可有几名班主任？ | 主班主任／副班主任权限是否不同 |
| Q-015 | 学生档案和若依登录账号是否一一对应？ | 建议业务档案与身份账号分离，并允许尚未开通账号的学生 |
| Q-016 | 需要保存哪些个人信息？ | 应遵循最小化原则；身份证、家庭住址、家长电话等敏感字段非必要不收集 |

## 3. 考试与成绩规则

| ID | 待确认问题 | 建议默认值或选项 |
| --- | --- | --- |
| Q-020 | 考试类型是否固定为月考／期中／期末？ | 用字典配置，避免写死 |
| Q-021 | 一次考试可否只覆盖部分班级或部分科目？ | 允许，并显式配置范围 |
| Q-022 | 科目满分是科目固定还是每次考试配置？ | 每次考试科目配置满分，更贴合实际 |
| Q-023 | 分数允许整数还是小数？ | 建议支持一位小数；以学校规则最终确认 |
| Q-024 | 总分是否自动计算？哪些状态计入？ | 自动计算；缺考等特殊状态的计入方式待确认 |
| Q-025 | 及格线、优秀线如何定义？ | 按满分比例配置，不固定写死 60／85 |
| Q-026 | 排名如何处理同分？ | 竞争排名（1,2,2,4）或稠密排名（1,2,2,3）二选一 |
| Q-027 | 不同选科组合是否需要同榜排名？ | 若存在新高考选科，首期可只做班内／同科统计 |
| Q-028 | 教师如何提交成绩？ | 支持暂存和批量提交；提交后锁定，退回才可编辑 |
| Q-029 | 是否需要 Excel 导入？ | 非核心；若做，必须先预检、展示错误行、确认后事务导入 |
| Q-030 | 重复导入或重复保存怎么处理？ | 不默认覆盖已提交／已发布数据；明确幂等键和冲突提示 |
| Q-031 | 是否允许删除成绩？ | 建议草稿可删除，提交后只能作废／更正并保留历史 |

## 4. 审核、发布与复核

| ID | 待确认问题 | 建议默认值 |
| --- | --- | --- |
| Q-040 | 审核是一级还是多级？ | 首期一级教务审核 |
| Q-041 | 审核退回是否必须填写原因？ | 必须 |
| Q-042 | 发布是否需要确认所有科目已提交？ | 需要，除非明确标为不参考／缺考状态 |
| Q-043 | 是否允许分班级分批发布？ | 建议允许，降低等待和并发冲突 |
| Q-044 | 复核由班主任、任课教师还是教务处理？ | 学生提交；教务分派或任课教师核对；最终改分权限需明确 |
| Q-045 | 复核申请是否有时限？ | 建议发布后若干工作日，具体天数待学校确认 |
| Q-046 | 同一成绩能否重复申请？ | 同一未结束申请存在时禁止重复；结束后是否再申请待确认 |
| Q-047 | 复核状态有哪些？ | 建议：待受理、处理中、无需修改、已更正、已驳回、已撤回 |
| Q-048 | 改分是否影响已发布总分和排名？ | 应重新计算并产生新版本／审计事件；是否通知相关学生待确认 |
| Q-049 | 谁可以撤回发布？ | 建议只有教务管理员，并强制填写原因和记录影响范围 |

## 5. 查询、统计与导出

| ID | 待确认问题 | 建议默认值 |
| --- | --- | --- |
| Q-050 | 学生查询哪些时间范围？ | 本人全部已发布考试，可按学期筛选 |
| Q-051 | 教师可看哪些学生与统计？ | 仅授权班级／科目；班主任可看本班汇总 |
| Q-052 | 基础统计的必选指标？ | 平均、最高、最低、及格率、优秀率、分数段、个人趋势 |
| Q-053 | 缺考等特殊状态是否进入分母？ | 必须逐指标说明，不能统一默认为 0 |
| Q-054 | 是否展示年级排名？ | 首期可不做，避免选科和不同试卷口径问题 |
| Q-055 | 导出是否包含个人敏感数据？ | 最小字段，按权限导出，并记录导出操作 |
| Q-056 | 是否需要家长打印成绩单或正式盖章报表？ | 首期不承诺正式证明类文书 |

## 6. 安全、审计与运行约束

| ID | 待确认问题 | 建议默认值 |
| --- | --- | --- |
| Q-060 | 是否接受复用若依验证码、JWT、RBAC 与数据权限？ | 接受，业务权限在其上细化 |
| Q-061 | 业务审计保存多久？ | 课程项目先保留全部实验数据；正式期限需校方规则 |
| Q-062 | 哪些动作必须记录前后值？ | 成绩更正、发布撤回、学生班级变更、任教关系变更 |
| Q-063 | 是否允许物理删除学生与已发布成绩？ | 不允许；采用状态／归档和审计 |
| Q-064 | 本地开发是否必须 HTTPS？ | 本地可 HTTP；真实部署必须由反向代理启用 HTTPS |
| Q-065 | 响应时间和并发目标？ | 先按课程演示规模提出可复现实验指标，不承诺未测试的 7×24 或容灾 |
| Q-066 | 支持哪些浏览器与终端？ | Windows 11/Fedora 上当前稳定版 Chrome/Edge；移动端仅响应式浏览待确认 |
| Q-067 | 数据库兼容范围？ | MariaDB 11.8 与 MySQL 8；SQL 和排序规则取两者兼容子集 |
| Q-068 | Redis/Valkey 是否存放业务真值？ | 不存成绩真值，仅用于验证码、Token、缓存等可恢复数据 |

## 7. 建议明确排除的范围

- 大学选课、课程容量、学分、GPA/CGPA、学位和正式成绩单。
- 排课、考场座位、监考、阅卷、题库、在线考试。
- 学费支付、工资、考勤、宿舍、图书馆、交通、门禁、访客和资产。
- 高考预测、志愿推荐、AI 分析和第三方招生数据。
- 短信、微信、邮件推送和家长门户，除非后续单独评审。
- 多租户、多学校 SaaS、移动原生应用和通用工作流引擎。

## 8. 评审建议

第一次范围评审应优先回答 Q-001 至 Q-009、Q-020 至 Q-031、Q-040 至 Q-049。回答后才能稳定用例图、状态图、数据字典和 ER 概念模型。其余问题可在非功能需求与详细设计前继续确认。
